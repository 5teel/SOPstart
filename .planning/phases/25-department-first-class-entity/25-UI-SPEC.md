# Phase 25 — UI Design Contract: Department as a First-Class Entity

> Visual and interaction contract for the four admin surfaces this phase ships. Generated by
> gsd-ui-researcher, consumed by gsd-planner and gsd-executor.
>
> All design decisions are derived from three validated sketch files
> (`sketches/departments/index.html`, `sketches/unified-block-library/index.html`,
> `sketches/team-departments/index.html`) and the project's canonical design token system
> (`sketch-findings-SOPstart`). No new design language is introduced.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no shadcn; Tailwind CSS 4 (PostCSS plugin) with CSS custom properties |
| Preset | not applicable |
| Component library | none — hand-authored components following project patterns |
| Icon library | Lucide React (existing) |
| Font — technical/mono | JetBrains Mono (400, 500, 600, 700) — all technical content, codes, timestamps, labels |
| Font — prose | Inter (400, 500, 600) — page sub-headings and long descriptions only |

Token source: CSS custom properties in `:root` matching the sketch palette exactly. All four
surfaces import from the existing `src/app/globals.css` token block (the `--paper`, `--ink-*`,
`--steel-*`, `--accent-*` variables already present in the project).

---

## Spacing Scale

Multiples of 4px only. Values match the sketch measurements directly.

| Token | Value | Phase 25 Usage |
|-------|-------|----------------|
| xs | 4px | Icon gap inside `.dchip` swatch + label; checkbox gap in picker options |
| sm | 8px | Gap between department filter buttons; gap between chips in `.c-dept` cell |
| md | 16px | Card inner horizontal padding; row padding (block library row, team row) |
| lg | 24px | Card inner full padding (`18px` in sketch — use `18px` as the spec value, see note) |
| xl | 32px | Vertical page gutter below header section |
| 2xl | 48px | Bottom page padding (prevents mobile chrome overlap) |
| 3xl | 64px | Not used in this phase |

**Exception — card inner padding:** The sketch uses `18px` for `.card .inner` padding, which
is not a strict 4px multiple. Use `18px` exactly (4.5 × 4) to match the sketch fidelity.
This is the only deviation and applies only to the department card inner container.

**Touch targets:** All interactive tap targets must be ≥ 44px tall. Filter buttons are
`8px 13px` padding on 12px text = ~34px — add `min-height: 44px` in the React implementation
to satisfy glove-friendly PWA requirement. This overrides the sketch's visual appearance
without changing the layout.

## Typography

Four sizes, two weights. JetBrains Mono is the default; Inter only for `.prose` wrappers.

| Role | Font | Size | Weight | Line Height | Usage |
|------|------|------|--------|-------------|-------|
| Page heading | JetBrains Mono | 22px | 700 | 1.2 | `h1` on each admin page |
| Section / card heading | JetBrains Mono | 15px | 700 | 1.3 | Department card name |
| Body / label | JetBrains Mono | 12px | 500 | 1.5 | Metadata lines, owner name, row text |
| Micro label | JetBrains Mono | 9–10px | 600 | 1.4 | Uppercase badges, stat labels, chip text, "OWNER" label |

Prose descriptions (page sub-headings) use Inter 12px at weight 400, line-height 1.5.

**Specific sizes extracted from sketches:**
- Department code under card name: 10px, uppercase, letter-spacing `0.06em`, `var(--ink-500)`
- Stats value: 17px, weight 700 (the only exception to the four-size system; it is a display
  number, not body text)
- Stats label: 9px, uppercase, letter-spacing `0.06em`, `var(--ink-500)`
- Owner "OWNER" label: 9px, uppercase, letter-spacing `0.08em`
- Owner badge (`.ownbadge`): 8px, weight 700, uppercase, letter-spacing `0.05em`
- Filter bar "DEPARTMENT" prefix label: 9px, uppercase, letter-spacing `0.10em`
- Column headers in team table: 9px, uppercase, letter-spacing `0.08em`

**Owner block (`.owner.empty`) — no-owner warning state:**

- Clicking this card and clicking "＋ New department" in the page header both trigger the
  same create-department modal/sheet

### Archived Department Visual Distinction

Active departments: rendered as cards in the grid (described above).

Archived departments: hidden from the main grid by default. A toggle "Show archived" (text
button, `font-size: 11px; color: var(--ink-500)`) appears below the grid when archived
departments exist. Archived cards, when shown, are rendered with:
- `opacity: 0.5` on the full card
- Colour stripe replaced with `var(--ink-300)` (greyed out)
- "ARCHIVED" micro-label in place of the overflow menu
- Stats still show live counts but are muted

(The sketch does not depict archived state — this is a sensible default derived from the
project's existing archive pattern on blocks. The executor should match the block archive
visual: greyed + badge label.)

### Create / Edit Department

Opens as a modal or bottom sheet (matches existing admin modal pattern; executor to reuse the
project's modal component). Fields:
- Name (text input, required)
- Code (text input, max 6 chars, auto-uppercased, e.g. "FRM", required)
- Colour (swatch picker — 8 options as defined in the colour section, required)
- Icon (emoji picker or single text char/emoji input, optional — rendered in the `.cdot`)
- Owner (searchable member selector — org member list, optional at creation)

Validation: name + code + colour required. Code must be unique within the org. No free-form
colour input.

### Empty State (no departments yet)

When no departments exist (fresh org):
- The grid renders only the add-new dashed card
- Below it: "No departments yet. Create your first department to start organising SOPs,
  blocks, and team members."
- Sub-text: "Each department has a named owner accountable for its procedures."

## Surface 4: Create-SOP Department Field

### Placement

In the blank wizard (`WizardClient.tsx` Step 1) and the AI draft path, the department
field replaces the existing SOP category field. The old free-text category field is hidden
from the form (the `category`/`category_tag` columns are retained read-only in the DB per
D-01, but the UI does not expose them for new SOPs).

### Component: Department Multi-Select Field

This is a form field within the wizard, not a bottom sheet. On desktop (≥ 768px) it renders
as an inline chip picker similar to `SubTradePicker`. On mobile (< 768px) it presents as a
bottom sheet (`DepartmentBottomSheet` — see below).

**Field label:** "Department" — 12px, weight 600, `var(--ink-900)`

**Selected state (chips in field):**
- Each selected department shown as a `.dchip` (same as block library chip spec — colour
  swatch + name, `var(--paper-2)` background, `var(--ink-300)` border)
- An "× All departments" chip shown when `allDepartments = true` — using `.dchip.all` style
  (cyan, `◇ All departments`)
- "＋ Add department" ghost button to open the picker

**"All departments" option:**
Rendered as the first option in the picker, matching the block library popover spec. When
selected:
- All individual department chips are cleared
- A single `.dchip.all` "◇ All departments" chip is shown
- Reflects D-04: SOPs can be org-wide

**"No department" (empty, no selection):** Acceptable — a SOP with no `sop_departments`
rows is visible to all org members per D-02 fail-open rule. The field is optional; no
required validation. Show helper text: "Leave empty to make visible to all members, or select
departments to restrict visibility."

### `DepartmentBottomSheet` (Mobile)

Replaces `CategoryBottomSheet` for the SOP wizard on mobile. The component replaces
`CategoryBottomSheet`'s props entirely:

```
Old: { categories: CategoryItem[]; activeCategory: string | null; onSelect; open; onClose }
New: { departments: Department[]; selectedIds: string[]; allDepartments: boolean;
       onSelect: (ids: string[], allDepts: boolean) => void; open: boolean; onClose: () => void }
```

Visual: same slide-up panel pattern as `CategoryBottomSheet`. Each department row: colour
swatch + name + checkbox. "All departments" option at the top (no swatch, distinct styling
matching the cyan chip convention). "Done" button at the bottom commits the selection.

## Cross-Surface: Department Chip Component Contract (`DChip`)

A single `<DChip>` component is defined once and imported by all four surfaces. This prevents
drift between surfaces.

### Props

```typescript
interface DChipProps {
  variant: 'department' | 'all-departments' | 'add';
  department?: { name: string; colour: string };  // required when variant = 'department'
  showOwnerStar?: boolean;  // appends ' ★' to label when true (team surface only)
  onClick?: () => void;     // for 'add' variant and interactive contexts
}
```

## Responsive Behaviour

### `/admin/departments` Page

- Desktop (≥ 768px): 2-column card grid
- Mobile (< 768px): single-column card grid (`grid-template-columns: 1fr`)
- The add-new dashed card spans full width at the bottom of the grid in both breakpoints
- Touch targets on overflow menu (`⋯`): pad to `44px × 44px` hit area

### Block Library (`/admin/blocks`)

- Desktop (≥ 768px): full row layout — kind icon + name + chips + action buttons in one row
- Mobile (< 768px): stacked row — kind icon + name on top line, chips on second line, action
  buttons moved to an overflow `⋯` menu (kebab) to prevent horizontal overflow
- Department filter bar wraps (`flex-wrap: wrap`) at all breakpoints
- The "Departments ▾" popover on mobile: render as a bottom sheet instead of an absolute
  popover (avoids viewport clip)

### Team Management (`/admin/team`)

- Desktop (≥ 768px): three-column row layout as specified (Member | Role | Departments)
- Mobile (< 768px): the Departments column is collapsed into the member row as a second line
  of chips; the Role `<select>` is moved below the name; the action column becomes a top-right
  kebab. The column headers are hidden on mobile (layout collapses to a card-per-member
  pattern)
- The department picker popover on mobile: render as a bottom sheet

### Create-SOP Wizard — Department Field

- Desktop (≥ 768px): inline chip picker within the wizard form
- Mobile (< 768px): tapping "＋ Add department" opens `DepartmentBottomSheet` slide-up
  panel; selected chips display inline in the field after the sheet closes
