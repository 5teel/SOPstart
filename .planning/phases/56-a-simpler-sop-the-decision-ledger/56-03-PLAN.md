## Planner decisions recorded here

- **Attachments use one FK column per level** (`sop_id`, `section_id`, `focus_step_id`, exactly one non-null) rather than a polymorphic `(target_kind, target_id)`: a polymorphic id has no FK, so deleting a section or step would leave orphan label rows — D-12 forbids orphans. Same intent as the orchestrator's "attachment table", stronger guarantee.
- **The ledger has no authenticated INSERT policy.** D-07's INSERT channel is the server writer `recordDecision()` (service role, org and actor from the session — 56-05). An own-actor INSERT policy would still let any org member put a decision the system never made into the audit trail through PostgREST. RLS on `decisions` is therefore one SELECT policy (admin / safety_manager, org-scoped); INSERT is revoked from anon and authenticated. Append-only (no UPDATE / DELETE for anyone) is exactly as D-07 states.
- **Backfill runs only while the ledger holds no live rows**, so a Management-API re-run of the file after go-live can never double-log a decision that `recordDecision()` already wrote.
- **Self-added assignments** (`assignment_type = 'individual'` and `user_id = assigned_by`) are not backfilled, matching the live path where selfAddSop is allowlisted (RESEARCH A7).
