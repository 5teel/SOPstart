<objective>
Make the Content Library's primary CTA open a working create form (DED-01 criterion 1, D-03), and first close the security hole that exposing `createBlock()` to a client form would open.

Purpose: `/admin/blocks/new` currently matches `[blockId]`, `getBlock('new')` returns null and `notFound()` fires on every click. The fix is a small static route whose client form submits through the existing `createBlock()`. But `createBlock()`'s input schema today accepts a service-role override carrying a caller-supplied organisation id that skips `requireAdmin()` entirely (`src/actions/blocks.ts` ~lines 56-70, 140-145). No client component imports `createBlock` yet, so that override has never been reachable from a browser; the new form is the first client import, which would make it a network-reachable, unauthenticated, cross-tenant write — the exact class Phase 46 CR-01 removed from the sibling `addBlockToSection` (see `src/lib/builder/section-blocks-core.ts`). Task 1 removes it the same way before Task 2 imports the action into a client component.

Decision note for the orchestrator (D-03 "kind (reuse SectionKindPicker)"): not followed literally, on evidence. `SectionKindPicker` lists `section_kinds` rows (slugs `hazards`, `steps`, `content`, `signoff`, plus the parser kinds), returns a `sectionKindId` UUID rather than a slug, and its copy and buttons are section-specific ("Pick a kind for this section", "Section title", "Add section"; its only consumer is `AddSectionButton`). Block `kind_slug` must equal the BlockContent discriminator (`hazard`, `ppe`, `step`, `emergency`, `custom`) or the snapshot-on-add check in `section-blocks-core.ts` rejects the block with "Block kind/content mismatch", so a block created from a section kind could never be added to a SOP. The form reuses the Content Library's own kind vocabulary instead, moved into one shared module so the library filter and the form cannot drift (CLAUDE.md 2026-09-27). D-03's "org/global scope" field follows `SaveToLibraryModal` as it is today: Phase 25 retired global scope, so the modal has no scope control and the form sends `scope: 'org'`.

Output: `src/lib/blocks/create-block-core.ts`, a hardened `createBlock()`, `src/lib/blocks/block-kinds.ts`, `/admin/blocks/new` + `NewBlockForm`, journeys + capability-matrix updates, the reserved-segment guard and new-block spec live.
</objective>
