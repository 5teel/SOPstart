## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin → diff page | Admin views two versions; superseded versions must be fetchable (admin client). |
| worker → SOP card | Worker sees the updated badge; computation must be org-scoped (worker can only see own completions). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-05-01 | Information Disclosure | Diff page leaks another org's SOP versions via admin client | mitigate | Admin-only route; the diff server action verifies both version ids belong to the caller's org before fetching (self-enforced org-scope). |
| T-23-05-02 | Tampering | Updated badge derived from a hardcoded literal (dead feature) | mitigate | Badge derives from published_at-vs-last-completion prop; 23-00 stub + grep gate assert real-data derivation (CLAUDE.md 2026-06-05). |
| T-23-05-03 | Information Disclosure | Worker's updated-badge query reads another worker's completions | mitigate | Last-completion query is RLS-scoped to the worker (sop_completions worker policy); kiosk roster attribution does not widen read scope. |
| T-23-05-SC | Tampering | npm installs | accept | No package installs (RESEARCH § Package Legitimacy Audit: none). |
</threat_model>
