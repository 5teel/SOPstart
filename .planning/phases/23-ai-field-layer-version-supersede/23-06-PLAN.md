<objective>
Reconcile D-11 roster name-select login with Supabase auth/RLS via the RESEARCH-recommended per-org KIOSK ACCOUNT model, and ship the worker+supervisor instance sign-off chain (AFL-VER-05). Workers on a shared device pick their name from the org roster to sign in (no password); the selection is captured as `roster_worker_id` (attribution FK) on `sop_completions` while `worker_id` keeps the kiosk account uid (satisfies existing RLS unchanged). Completing the SOP records the worker self-signature; the supervisor counter-signs via the existing review path (D-09/D-10). NO RLS rewrite — the kiosk account is a valid org member.

Purpose: AFL-VER-05 (completing the SOP IS the legal signature, bound to the roster identity) + D-11 (passwordless floor-usability on shared devices). This is the central security-sensitive change — the threat model addresses cross-tenant identity spoofing, kiosk session scope/longevity, RLS isolation under the kiosk model, and binding the selected identity to immutable signature records.
Output: kiosk login route + RosterSelector + submitCompletion roster extension + recordSignature + supervisor counter-sign wiring + runtime insert test + human UAT.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shared kiosk device → kiosk Supabase session | One long-lived org-scoped session shared by all roster workers on the device. |
| client → submitCompletion (rosterWorkerId) | Untrusted roster id crosses here — cross-tenant attribution attack surface. |
| client → recordSignature | Untrusted signature insert — must be service-role + org-scoped + append-only. |
| kiosk account → RLS | Kiosk account is a role='worker' org member; existing org/sub-trade/dept policies apply unchanged. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-06-01 | Spoofing | Client sends a rosterWorkerId from another org (cross-tenant attribution) | mitigate | submitCompletion validates rosterWorkerId ∈ organisation_members for the kiosk session's org BEFORE writing (Pitfall 4); roster id never written if not same-org. |
| T-23-06-02 | Elevation of Privilege | Kiosk account escalates to admin | mitigate | Kiosk organisation_members.role is permanently 'worker'; requireAdmin/JWT user_role guards on all admin actions; /login/kiosk redirects authed admin/safety_manager away. |
| T-23-06-03 | Information Disclosure | Kiosk session reads another org's data | mitigate | current_organisation_id() reads the kiosk account's JWT org claim (custom_access_token_hook); existing org-scoped RLS unchanged — no anon session (Option B rejected). |
| T-23-06-04 | Tampering | Worker forges a signature directly into sop_completion_signatures | mitigate | No authenticated INSERT policy (00038); recordSignature uses service-role with org-scope check; append-only (no UPDATE/DELETE). |
| T-23-06-05 | Repudiation | Self-reported roster pick is not cryptographically proven | accept | Explicit D-11 tradeoff (floor-usability over cryptographic strength); mitigated by supervisor counter-sign (D-10) adding a second name-select; same risk surface as a logged-in worker leaving a device unlocked. Documented in SUMMARY. |
| T-23-06-06 | Tampering | Stolen kiosk session creates completions attributed to anyone | accept/mitigate | Kiosk cannot escalate or cross orgs (role='worker', org-scoped); attack surface equals an unlocked logged-in worker device. Accepted per D-11; recommend device lock + periodic kiosk re-auth. |
| T-23-06-07 | Tampering | Signature-write shipped green but never exercised (CLAUDE.md 2026-06-15 junction-write blind spot) | mitigate | Task 3 adds a runtime signature-insert test (or UAT-routed fixme) that performs a real insert as an authenticated principal — not source-contract only. |
| T-23-06-SC | Tampering | npm installs | accept | No package installs (RESEARCH § Package Legitimacy Audit: none). |
</threat_model>
