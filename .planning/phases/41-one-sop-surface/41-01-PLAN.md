## Rendering model (D-03 / ROADMAP hard requirement — decided here, before any surface work)

**`/sops` stays a client component; the three admin views become `next/dynamic({ ssr: false })` client lenses gated by `useIsAdmin()` and fed by self-guarding server actions.** This is the second of the two ROADMAP-sanctioned shapes ("keep the list client-side and code-split the admin lenses"). Rationale:

1. D-03 requires every worker behaviour be preserved *verbatim*. `/sops` already has a working offline data layer (`useAssignedSops`, `useSopSync`, Dexie, self-add/remove, refresher dates, search); the smallest diff that guarantees verbatim preservation is "add to the existing client tree", not "rebuild the host as a server shell".
2. The admin data is already action-shaped, not page-shaped: `listGovernanceQueue`, `listOrgTree`, `listGrants` and `ensureSopCollections` are `'use server'` functions that each self-guard via `requireAdminContext()` — verified by direct read at plan time (`src/actions/governance.ts:324`, `src/actions/org-model.ts:48/120`, `src/actions/grants.ts:56/127/396`), which closes RESEARCH assumption A1. They are callable from a client `useQuery` with no server-side change.
3. `next/dynamic({ ssr: false })` is the exact mechanism this repo's bundle gate already knows how to verify (`WalkthroughSwitcher` → `DesktopWalkthrough`), so SUR-05 is provable with the machinery this plan generalises rather than with unproven RSC code-splitting semantics.
4. `useIsAdmin()` already exists and costs no fetch — role is resolved once server-side in `(protected)/layout.tsx` and threaded through `RoleProvider`.

Every later plan in this phase implements that model; 41-02 is the first to build on it. Which lens components exist, how they load, scope ordering and skeleton states remain Claude's discretion per CONTEXT.

Purpose: SUR-05 is a phase-failing condition. The existing gate is hardcoded to a single route (`scripts/check-bundle-size.ts:44-53`), so it would stay green after the merge while proving nothing about the list route. Everything downstream depends on this gate being real before the first line of surface code is written.
Output: two-route `.bundle-baseline.json`, generalised gate scripts with marker self-validation, `phase41` project + 5 stub specs, one lint guard.
