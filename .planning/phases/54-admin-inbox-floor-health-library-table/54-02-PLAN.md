<objective>
Make `/governance` the admin's home for the work: a server-rendered inbox of one-action rows built from data that already exists, with counted chips and an All clear state, the existing governance row (and its approval gating) reused verbatim, and every door (header, two legacy shims, journeys, roles) pointing at it.

Purpose: ADM-01. The inbox is the goal-state surface — rows drain to "All clear". The floor column lands beside it in 54-03; the table replaces the `/sops` lenses in 54-04.

Output: `src/lib/governance/inbox.ts` (unit-tested), `/governance` page, `GovernanceInbox`, restyled `GovernanceQueueRow`, header + shims + journeys + roles + capability matrix, and every spec that pinned the old destinations repointed in the same commit.

Decisions made here (documented deviations):
- Server page, not a client lens: `GovernanceQueueRow` and `OwnerPicker` finish with `router.refresh()`. That only removes a cleared row when the data is server-rendered — the old `useQuery` lens left rows stale until `staleTime`. Ages are pre-rendered server-side (`MillerSop.age`), so nothing time-dependent runs during hydration (2026-06-08).
- Overdue rows keep GovernanceQueueRow's **Confirm current** button (the one action that clears the flag) and the row title links to the builder for the review itself. D-02 lists "Review (→ builder)" as the verb, but D-03 preserves GovernanceQueueRow's branches and `confirmSopCurrent` has no other caller — a builder-only button would orphan REV-04.
- No row uses "Finish": none of D-02's three sources produces a row whose clearing action is finishing a draft (drafts surface under their governance flag). Stuck / failed conversions get **Retry** → builder (research Q1: the builder's parse-state panel owns retry). **Add** → `/admin/sops/new` plain (the creation flow takes no machine parameter).
- `/admin/governance`'s legacy `?filter=` is dropped: the inbox has no flag-filter param; a bookmark lands on the whole inbox.
</objective>
