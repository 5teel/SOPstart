<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /api/sops/[sopId]/source-url | Untrusted user requesting a signed URL; RLS gates org membership |
| Source signed URL → Browser pdfjs | Untrusted PDF content rendered in user's tab via pdfjs; sandboxed (pdfjs is server-trusted, but content is admin-uploaded) |
| Builder canvas ↔ source pane (in-memory context) | Same-origin trust boundary; no XSS exposure if React rendering is escaped (Tailwind defaults) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-02-01 | Information Disclosure | Signed URL endpoint | mitigate | RLS gate on `sops` row; 5-min URL expiry; private bucket |
| T-21-02-02 | Tampering | Malicious PDF served to admin | accept | Admin uploaded the file themselves; pdfjs is the standard browser PDF rendering library; no plugin surface |
| T-21-02-03 | Denial of Service | Large PDF (100+ pages) bundle | mitigate | Lazy-render pages beyond first 50 (Spike 002 signal #2) |
| T-21-02-04 | Spoofing | Reverse-channel block-click handler exposed | mitigate | Context is React-internal, no DOM event API; cannot be triggered from cross-origin script |
| T-21-02-05 | Tampering | Bundle leak — pdfjs ships to worker route | mitigate | `scripts/check-bundle-size.ts` chunk-existence assertion (CI gate, blocks merge) |
</threat_model>
