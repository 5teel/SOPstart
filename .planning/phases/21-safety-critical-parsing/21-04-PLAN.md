<objective>
Implement the publish gate — the third independent verification layer (D-CV2-04 Layer 3).
Every block in a parsed SOP must be explicitly verified by an admin before publish.
No bulk-verify, no skip-all. The 2.5-minute friction at 50 blocks IS the safety feature
(Spike 004 verdict). Also closes the four `SCP-PARSE-*` requirements that complete the
Phase 20 contract: step-level provenance on every block, builder-as-review surface,
side-by-side viewer integrated, AI reviewer in pipeline.

Purpose: Make publish impossible without one-block-at-a-time eye-on-content review.
Defence in depth: UI disable + server-side rejection.

Output: A `<VerifyChecklistGate>` sidebar pane in the builder, a server-side publish
endpoint that gates on `sop_section_blocks.verified_by_admin_id`, and the final
wiring that closes all remaining Phase 21 requirements.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → POST /api/sops/[sopId]/publish | Admin attempts to publish; server gates on verification status |
| UI checklist → server actions | Each verify call is `'use server'` boundary; RLS + role check |
| DB trigger (Wave 1) | Clears verification on content change — content-change detection MUST be accurate (false-negative = security gap, false-positive = annoying UX) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-04-01 | Elevation of Privilege | Admin client bypasses UI to publish unverified SOP | mitigate | Server-side gate in publish endpoint queries `sop_section_blocks.verified_by_admin_id IS NULL`; UI-only gate would be defeatable |
| T-21-04-02 | Tampering | Direct UPDATE to `sop_section_blocks` setting fake verifier | mitigate | RLS: only admin role of the owning org can UPDATE; `verified_at` is set by trigger or server action, NOT user-supplied |
| T-21-04-03 | Repudiation | Admin denies they verified a block | mitigate | `verified_by_admin_id` references `auth.users(id)` (immutable except ON DELETE SET NULL); `verified_at` immutable post-set; pair forms an audit trail |
| T-21-04-04 | Denial of Service | 1000+ blocks on a huge SOP | accept | Spike 004 measured 50 blocks at 2.5min; 1000 blocks at the same pace = 50min — admin pain, not a security issue. Document in 21-04-SUMMARY as Visy pilot signal |
| T-21-04-05 | Tampering | Bulk-verify accidentally added in future PR | mitigate | Static-analysis test in Task 1 fails CI if `'approve all' / 'bulk' / etc.` strings appear in `VerifyChecklistGate.tsx` |
| T-21-04-06 | Information Disclosure | block_provenance.source_ref leaks storage path | mitigate | RLS gates `sop_section_blocks` by org; the storage path is signed-URL-only accessible |
</threat_model>
