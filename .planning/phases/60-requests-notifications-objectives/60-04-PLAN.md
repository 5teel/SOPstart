## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `raiseRequest` / `withdrawRequest` / `answerRequest` / `listMyRequests` | every export of a `'use server'` file is a POST endpoint |
| server action → service-role request core | the core bypasses RLS; the action supplies the session org |
| cron (no session) → `raiseRequestAsAgent` | organisation passed explicitly by a header-authenticated route |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-60-13 | Elevation / Tampering (cross-tenant request via a client-supplied subject id) | `raiseRequest`, `subjectInOrg` | mitigate | org from `getSessionContext()` only; every core query `.eq('organisation_id', <session org>)`; subject verified in that org before insert |
| T-60-14 | Elevation (worker answers a request) | `answerRequest` | mitigate | `canAnswerRequests(role)` from the session before any write |
| T-60-15 | Tampering (double answer race) | `claimOpenRequest` | mitigate | update filtered on `state = 'open'`; zero rows returns before the ledger row and the notification |
| T-60-16 | Elevation (trust flag on a client-reachable action) | `raiseRequestAsAgent` | mitigate | lives in a plain server-only module; zod `.strict()` refuses any agent / org / user field on the actions; spec asserts no action or component imports it |
| T-60-17 | Spoofing (forged agent name) | agent rows | mitigate | name checked against `AGENT_NAMES` at runtime and by type |
| T-60-18 | Repudiation (answer not logged, or logged twice) | `answerRequest` | mitigate | exactly one `recordDecision` after the claim; registry + sweep; `logged` drives the receipt wording |
| T-60-19 | Information disclosure (PII in an immutable ledger row) | ledger details | mitigate | summaries are literals; details carry ids, titles and notes only, never an email |
| T-60-20 | Denial of service (request flood) | `raiseRequest` | accept | authenticated org members only, notes capped at 500; no notification fan-out on raise |
