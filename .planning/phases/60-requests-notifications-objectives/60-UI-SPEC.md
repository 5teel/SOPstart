# Phase 60 — UI Design Contract

> Visual and interaction contract for: the site overview (detail pane with nothing selected), the bell, the Requests tab in the Office, the request composer, the "Ask someone to do this" picker, the worker-side ask row, objective lines and their editor, and the notification rows. Generated by gsd-ui-researcher (auto mode), verified by gsd-ui-checker.
> Governing sources: `60-CONTEXT.md` (D-01..D-13 and amendments A-01..A-12, binding), `60-RESEARCH.md` (F-01..F-23), `59-UI-SPEC.md` (structure, tokens, copy voice, receipt idiom, agent chip, `ReasonDialog`, test-id conventions — this spec extends it and repeats nothing it already fixes), `one-screen-site.md` (overview = objectives · notifications · open requests; "objectives read as metadata, not as content"; no toasts over a SOP), `src/styles/blueprint-theme.css` (the only place tokens live).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom paper/ink system; no `components.json`; shadcn gate not applicable) |
| Preset | not applicable |
| Component library | none — hand-built; native `<select>`, `<textarea>`, `<input type="date">`, radio inputs styled with tokens |
| Icon library | Lucide React (new this phase: `Bell`, `ChevronRight`, `UserPlus` only if a row needs an icon; everything else already imported by the shell) |
| Font | Inter (UI), JetBrains Mono via `.mono` (meta, counters, section labels, chips) |
| Theme | Paper only. No dark surface is introduced; dialog scrims are `bg-ink-900/40` |
| Enforcement | `tests/lint/design-tokens.spec.ts` — no raw palette classes, no bare hex, no `[Npx]` sizes, radius vocabulary of four (`rounded`, `rounded-lg`, `rounded-2xl`, `rounded-full`) |

**New tokens: none.** Opacity tints use the utility form (`bg-accent-ok/10`, `bg-ai/10`, `bg-accent-decision/10`, `bg-accent-measure/10`). New utility families to grep in the compiled CSS before pushing (CLAUDE.md 2026-09-28): `size-5`, `min-w-5`, `w-72`, `line-clamp-2`, `bg-accent-measure/10`, `bg-ai/10`, `bg-accent-decision/10`, `bg-ink-100`, `h-18`.

**Bundle rule (A-07, binding on this spec):** the only static additions to the home bundle are the bell (icon + count), the text-only `ObjectiveLine`, the one `Make a request` button on the worker machine panel and the `Ask ›` / `Make a request` triggers. Everything else — the overview body, the composer, the ask picker, the objective editor, the Requests tab — is a `next/dynamic({ ssr: false })` module with **no CSS import**. A surface that appears from a lazy module reserves no space (the 57/59 idiom); the one-frame shift is accepted.

| Phone | CSS collapse only (57 D-21): the pane is `w-full` below `lg`; nothing is hidden by JS |

### Notifications section (NTF-01)

Read through the browser Supabase client under RLS (A-06) — no server action on any path of this section.

| Part | Spec |
|------|------|
| Row | `<button type="button" data-testid="notification-row" data-kind data-unread>` full width, `flex gap-3 border-b border-ink-100 px-4 py-3 min-h-tap text-left hover:bg-paper-2 focus-visible:outline-2 focus-visible:outline-accent-step` |
| Unread dot | `size-3 mt-1 shrink-0 rounded-full bg-accent-measure` (info colour); a read row keeps the same width with no dot (`size-3` spacer) so text does not jump |
| Line 1 | kind word `mono text-meta uppercase text-ink-500` left, age `mono text-meta text-ink-500` right (`relativeWhen`; absolute NZ time in `title`) |
| Line 2 | the stored title, `text-ui` `line-clamp-2`; unread `font-semibold text-ink-900`, read regular `text-ink-700` |
| Count shown | up to 5 unread, newest first; beyond 5 a `Show {n} more` text button (`min-h-tap text-ui text-ink-500 hover:text-ink-900`) |
| Show read | a `Show read` text button under the unread rows, **always present once any read row exists**; toggles to `Hide read`; reveals the last 10 read rows, regular weight, no dot. No read rows ever → the button is absent. Read rows only: "Nothing unread." (`text-ui text-ink-500`) above `Show read` |
| Opening | press → the row dims `opacity-60` → the browser client sets `read_at` (awaited, 3 s ceiling; **a failed mark-read still navigates** — read state is secondary) → goes to the stored `place`: a `?place=` address calls the shell's `select()`, a `/sops/...` address navigates. Overview-bound kinds (request answered) just scroll to My requests |
| Nothing over a SOP | notifications never appear as a toast, popover or badge on the focus screen. The overview and the bell are the only places they live (D-09, focus rule) |
| Stale due state | opening or merely loading an unread "asked" notification re-reads the worker's assignments so the machine badge and the Now card show it without a reload (RESEARCH Pitfall 8) |

### Notification copy per kind (NTF-02)

Titles are fixed sentences written by the server from literals plus a SOP title or a first name — no ids, no free text from a note. "Name" is `full_name`, else "Someone".

| Kind (word on line 1) | Title | Opens |
|-----------------------|-------|-------|
| Approve | "Your approval is next on {SOP title}." | `/?place=office` (the Inbox row) |
| Review | "{SOP title} is due for you to review by {12 Nov}." / overdue: "{SOP title} was due for review on {3 Oct}." | `/?place=office` |
| Sign-off | "{Name} finished {SOP title} and is waiting for you to sign off." | `/?place=office` |
| Answered | accepted: "Your request about {about} was accepted." · declined: "Your request about {about} was declined." · observe accepted: "{Name} accepted — they'll observe you on {SOP title}." · a declined ask you made: "{Name} can't do {SOP title}." | the overview (scrolls to My requests) |
| New version | "{SOP title} has a new version (v4)." | the SOP's browse address |
| Asked | "You've been asked to do {SOP title}." | the SOP's browse address |

The decline reason is not in the title; it shows on the asker's My requests row.

### Objectives section (OBJ-02)

Same line as everywhere else (below), but the prefix is the **place's name**, not the word "Objective": `Site · …`, `Press · …`. Site first, then departments in list order. Each objective is a row (`px-4 py-2`, no border, `gap-1`). Agent-set rows carry the unconfirmed controls underneath. Read-only here; departments are edited from their own panel, the site from this section.

| Editor state | What shows |
|--------------|-----------|
| Admin / safety manager, no site objective | `Set a site objective` — dashed button `min-h-tap w-full rounded-lg border border-dashed border-ink-300 px-3 text-left text-ui text-ink-500` (the existing This SOP idiom). Opens the inline editor in place |
| Admin / safety manager, site objective set | the line + `Change` text button (`min-h-tap px-2 text-ui text-ink-500 hover:text-ink-900`) |
| Anyone else | the line only; the section is absent if there are none |

### My requests section (RQS-01, D-02, A-03)

Three groups in one list, in this order, each row `border-b border-ink-100 px-4 py-3`:

1. **Asked of you** — person-targeted asks still in force, raised in the last 14 days, max 3 **(picked)**. Role asks never appear here (no per-person decline, A-03; they simply show as due on the machine).
2. **You asked** — your open requests and the asks you made that are still in force, max 5, then `Show all {n}` text button.
3. **Answered** — the last 3 answered, withdrawn or declined of yours.

| Part | Spec |
|------|------|
| Row line 1 | about-title (`text-reading font-semibold` truncated; a SOP is a link to `focusHref(id, { from: null })`; a machine or "Whole site" is plain text) + state chip right |
| Row line 2 | `mono text-meta text-ink-500`: "{Kind} · {age}" — kinds in words **Change a SOP · New SOP · Observe me · Asked of you · You asked {Workers\|Name}** — and for answered rows "answered {12 Nov}" |
| Row line 3 | your note, `text-ui text-ink-700 line-clamp-2` in quotes. Answered rows add the answer: `text-ui text-ink-900` "{Name}: “{answer note}”"; accepted with no note: "Accepted by {Name}." |
| Agent-raised | the Phase 59 agent chip beside the title (`rounded mono text-meta uppercase px-2 py-1 bg-ai/10 text-ai border border-ai/40`, word **agent**) |
| State chip | `rounded mono text-meta font-semibold uppercase px-2 py-1`. **Open** `bg-paper-2 text-ink-700` · **Accepted** `bg-accent-ok/10 text-accent-ok` · **Declined** `bg-paper-2 text-ink-900 border border-ink-300` (neutral outline — a decline is an answer, not an error, so red stays scarce) · **Withdrawn** `bg-paper-2 text-ink-500` · **Asked of you** `bg-accent-measure/10 text-accent-measure` |
| Action | one button per row, below the text (`min-h-tap`, the 59 neutral row-button style): **Withdraw** on your open request (one tap, no dialog; receipt "Withdrawn." — it is not a decision, so no ledger suffix); **Decline** on an ask of you (opens the reason dialog); **Stop asking** on an ask you made that is still in force (reason dialog) |
| Section header action | `Ask for a new SOP` (secondary button, right of the heading) opens the composer with kind fixed to new SOP (see Composer). Hidden for admin and safety manager (they write SOPs directly) |
| Receipts | a successful action turns that row into a receipt row for 10 s — `Check` `text-accent-ok` + text (below) — then the row moves to its new group after the refetch. `role="status"` `aria-live="polite"`; the row keeps its height so nothing jumps |

**Worker decline of an ask (reason dialog, reuses `ReasonDialog`):** title "Decline {SOP title}?" · body "{Name} will see your reason. It stops being due for you." · label "Why can't you do it?" · confirm **Decline** (`ink` tone) · cancel **Keep it**. Success receipt "Declined · logged in the decision ledger".

**Stop asking (reuses `ReasonDialog`):** title "Stop asking {Workers\|Name} to do this?" · body "It stops being due for {everyone in that role\|them}." · label "Why are you stopping it?" · confirm **Stop asking** (`ink`) · cancel **Keep asking**. Receipt "Stopped asking · logged in the decision ledger".

**Accept** has no dialog (it does the obvious thing, D-04). Receipt text goes in the header receipt slot and, because it can carry a link, **holds until the next action or a tab change rather than 10 s** **(picked)**:

| Kind | Receipt |
|------|---------|
| Change a SOP | "Accepted · logged in the decision ledger" + link **Open the SOP** — the editor address for admin and safety manager, the browse address for a supervisor (F-23) |
| New SOP | "Accepted · logged in the decision ledger" + link **Start the SOP** → the blank wizard pre-filled with the machine |
| Observe me | "Accepted · logged in the decision ledger. They've been told you'll observe." (no link; the asker's notification names you) |
| Ledger write failed | "Accepted, but it didn't reach the decision ledger. Tell an admin." (`text-accent-escalate`, no link) |

**Decline** opens `ReasonDialog`: title "Decline this request?" · body "{Name} will see your answer." · label "Why are you declining it?" · confirm **Decline request** (`ink` tone — a decline is an answer, not a destructive action) · cancel **Keep it open** · field helper "10 characters or more." Receipt "Declined · logged in the decision ledger".

Clearing follows the 59 five-step rule exactly (pending → receipt → 200 ms collapse → focus to next row's first button, else the empty heading → failure line `role="alert"`). Race: a request already answered by someone else shows "Someone already answered this." under the row and the row leaves after the refetch.

## The request composer (RQS-01, D-01, F-22)

A focused dialog, the screen recessed — the 59 `ReasonDialog` shell (**(picked)** extract its scrim + panel markup into one shared `DialogShell` used by both; lazy chunk, no CSS import). `role="dialog" aria-modal="true"`, scrim `fixed inset-0 z-50 grid place-items-center bg-ink-900/40 p-4`, panel `flex w-full max-w-md flex-col gap-4 rounded-2xl bg-paper-1 p-6`. Esc closes only the dialog.

### Where it opens from

| Trigger | Where | Offers |
|---------|-------|--------|
| **Make a request** (secondary button, `min-h-tap w-full rounded-lg border border-ink-300 bg-paper-1 text-ui font-semibold text-ink-900`, `mt-2`) | footer of the worker `MachineBody`, under the SOP rows. Worker and supervisor panels; **not** the admin panel (admins have New SOP and the editor) | all three kinds. About for Change / Observe = a native `<select>` of this machine's SOPs; for New SOP = this machine (read-only line) |
| **Make a request** (text button `min-h-tap text-ui text-ink-700 underline-offset-2 hover:underline`) | inside the browse-state summary card (`focus-summary`), last row, **live SOPs only** (hidden on drafts, superseded versions and the walk state) | Change a SOP and Observe me; About is this SOP (read-only line). New SOP is not offered here |
| **Ask for a new SOP** | My requests header on the overview | New SOP only; About = native `<select>` of machines plus **Whole site** |

Nothing in the walk state or beside the steps ever offers a request (focus rule).

### Fields (top to bottom)

| Field | Spec |
|-------|------|
| Title | `text-lg font-semibold`: "Make a request" (overview trigger: "Ask for a new SOP") |
| Kind | label `text-ui font-semibold` "What do you need?"; `role="radiogroup"` of stacked options, each `<label>` `flex flex-col gap-1 rounded-lg border p-3 min-h-tap`, native radio `sr-only`, selected `border-ink-900 bg-paper-2`, unselected `border-ink-300 bg-paper-1`, `focus-within:outline-2 focus-within:outline-accent-step`. Hidden entirely when only one kind applies (overview) |
| About | read-only line `text-ui text-ink-700` "About · {SOP title or machine}" when fixed, else a labelled native `<select>` (`min-h-tap rounded-lg border border-ink-300 bg-paper-1 px-3 text-ui`) "Which SOP?" / "Which machine?" |
| Note | label by kind: Change **"What needs changing?"** (required) · New **"What is the job?"** (required) · Observe **"Anything we should know?"** (optional). `<textarea>` `text-reading rounded-lg border border-ink-300 bg-paper-1 p-3`, 4 rows, `maxLength` 500; counter `mono text-meta text-ink-500` "{n} / 500" right-aligned; required helper "10 characters or more." (turns `text-accent-escalate` only after a blur under 10) |
| Error | `text-ui text-accent-escalate` `role="alert"`: "That didn't work. Nothing was sent — try again." (or the server's plain message) |

## Objectives as metadata (OBJ-01, OBJ-02, D-10, D-11, A-01)

### The line (`ObjectiveLine` — static, text only)

One shared line, `data-testid="objective-line"`, `data-agent`, `data-confirmed`. **Never a card, never a border, never beside an open SOP's steps.**

```
Objective · Zero lost-time injuries this quarter · by 12 Nov · set by Jane
Objective · Forming runs at 96% · set by SOPstart assistant  [agent] [Unconfirmed]
Objective · Clear the backlog · was due 3 Oct · set by Jane
```

| Part | Spec |
|------|------|
| Line | `mono text-meta text-ink-500`, `min-w-0 break-words`, wraps (≤ 200 chars; this is the only place the text is read, so it never truncates). Prefix `Objective` (or the place's name on the overview) |
| Text | the statement in `text-ink-700` — slightly stronger than the metadata around it; same 11 px mono, **not** `text-reading`. It must read as a label, not as content (`one-screen-site.md`) |
| By date | "by 12 Nov" (`en-NZ`, fixed `Pacific/Auckland`, year only when not this year); past due → "was due " + the date in `text-accent-escalate font-semibold`. Same idiom as the review line |
| Set by | "set by {full name}"; no name → "an admin". Email only for admin and safety manager viewers **(picked)** so workers never see an admin's email address |
| Agent-set | "set by {agent}" + the agent chip (`bg-ai/10 text-ai border border-ai/40`) + an **Unconfirmed** chip (`rounded mono text-meta font-semibold uppercase px-2 py-1 bg-accent-decision/10 border border-accent-decision/40 text-ink-900` — amber lives in fill and border, the words stay dark per the 59 contrast rule) |
| Confirm | admin and safety manager only, in the lazy editor module: **Confirm** (`min-h-tap rounded-lg border border-ink-300 bg-paper-1 px-3 text-ui font-semibold text-ink-900`) under the line. Receipt "Confirmed · logged in the decision ledger". Changing the text also confirms it |
| Empty | for non-editors nothing renders at all — no "No objective" text |

| Surface | Placement | Editor controls |
|---------|-----------|-----------------|
| Site | overview, Objectives section (above) | Set / Change in the section |
| Department | the department panel in `ShellFrame`, directly under the department name `h2`, `mt-1` (a `deptMeta?(id)` slot — `ShellFrame` stays one-writer, no router) | `Set an objective` dashed row below the line for editors |

### Editor (`ObjectiveEditor` — lazy, admin and safety manager only)

Inline, in place of the line (not a dialog — setting an objective needs the page context behind it). Panel `flex flex-col gap-2 rounded-lg border border-ink-200 bg-paper-1 p-3`. Esc closes it only (capture, `preventDefault`).

| Part | Spec |
|------|------|
