# Phase 26.5 Plan 04: Proposal Lifecycle + Synthesis Pipeline Summary

**One-liner:** `agent-proposals.ts` gives the layer an always-pending, evidence-backed proposal lifecycle plus free-append memory writes; `synthesis.ts` wires it all together into `synthesizeSop` — embed via Voyage, tag/entity via Haiku, four signals in, memory + evidence-backed proposals + assessment out, all org-self-enforced and observable-on-failure.

## What Was Built

**Task 1 — `src/lib/ai-fields/agent-proposals.ts`:**
- `createLearningProposal(organisationId, sopId, { kind, description, evidence }, adminInsert?)` — always inserts `status: 'pending'` with a non-empty `evidence` payload via the injectable `AgentAdminInsertFn` seam (mirrors `approval.ts`'s `AdminInsertFn`). Default seam (`defaultAgentAdminInsert`) uses `createAdminClient()` and throws a `[agent-layer]`-prefixed error on failure.
- `approveProposal` / `declineProposal(organisationId, proposalId)` — flip `status` to `'applied'`/`'rejected'` + set `reviewed_at`, filtered by BOTH `.eq('id', proposalId).eq('organisation_id', organisationId)` — self-enforced org-scope since the service-role client bypasses RLS (CLAUDE.md 2026-06-15/2026-06-26). Approve does not itself edit SOP content this phase (D-13 comment in source).
- `appendMemory(organisationId, { sopId, scope, observation, signalSource, metadata })` — free append into `agent_memory`, no status/approval field.

**Task 2 — `src/lib/agent-layer/synthesis.ts`:**
- `synthesizeSop(sopId, organisationId)`: loads the published SOP's plain content (sections/steps/blocks, no `layout_data`) via `createAdminClient()` filtered on both `id` and `organisation_id`; builds the full-text pack via the existing `packSopForPrompt` (byte-identical serializer already used by voice Q&A); in parallel — embeds the whole SOP (`getVoyageClient().embed(..., model: EMBED_MODEL, inputType: 'document')`), extracts a summary/tags/entities via `getAnthropic()` at `SYNTHESIS_MODEL` (JSON-only prompt, same fence-stripping pattern as `verify-sop.ts`), and reads all four signals via `readAllSignals` (Plan 03). Then: best-effort per-block embedding into `block_agent_metadata` keyed by the junction id (D-02); free-append `agent_memory` observations derived from the signal bundle; evidence-backed `createLearningProposal` calls where a signal pattern justifies one (critical reviewer flags, majority-unverified blocks), capped at `MAX_PROPOSALS_PER_RUN = 3`; `deriveAssessment(bundle)` → `'fresh' | 'drifting' | 'needs-review'`; final upsert into `sop_agent_metadata` (`onConflict: 'sop_id'`) with `last_synthesis_status: 'ok'`.
- Every step (embed, tag-extraction, each signal reader, memory writes, proposal raises, block embeds) is independently try/caught — a single failure degrades gracefully rather than blanking the run. On any top-level failure, a distinct `[agent-layer] synthesis failed:` line is logged AND `last_synthesis_status='error'` / `last_synthesis_error` is recorded on `sop_agent_metadata` via a fresh `createAdminClient()` call (Pitfall 5 / 2026-06-02 VERIFY_MODEL-incident precedent — an all-failing fire-and-forget job must be observable).
- `triggerAgentSynthesis(sopId, organisationId)`: fire-and-forget wrapper — `synthesizeSop(...).catch(err => console.error('[agent-layer] synthesis trigger failed:', ...))`, never awaited, never throws.

Both spec files made live per the plan: `proposal-evidence.spec.ts` now statically imports `createLearningProposal`/`AgentAdminInsertFn` and runs a real fake-seam unit test (no live DB) plus source-contract checks for org-scoped approve/decline and gate-free memory. `synthesis-pipeline.spec.ts` stays source-contract (runtime AI calls deferred to `test.fixme`, since a real run needs live Voyage/Anthropic keys) — asserts shared-constant usage (no raw `'voyage-3`/`'claude-haiku` literals), `deriveAssessment`'s three return values, `triggerAgentSynthesis`'s `.catch`-without-`throw` shape, and every DB write setting `organisation_id` with zero `layout_data` reference. The D-04 "publish route wires triggerAgentSynthesis" test skips cleanly until Plan 26.5-05 wires the publish route (out of this plan's `files_modified`).
