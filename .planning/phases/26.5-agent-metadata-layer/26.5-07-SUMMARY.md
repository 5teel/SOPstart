# Phase 26.5 Plan 07: Builder Agent Layer Surface Summary

**One-liner:** `src/actions/agent-layer.ts` gives the builder admin-gated, JWT-safe reads of the machine layer plus proposal approve/decline; a new `⚇ Agent layer` toggle in `BuilderClient.tsx` reveals a purple, JetBrains-Mono, strictly read-only panel (SOP summary/tags/entities/embedding/links) and per-block metadata rows keyed by junction id — proven read-only by a real `react-dom/server` render, not just a grep.

## What Was Built

**Task 1 — `src/actions/agent-layer.ts`:**
- `requireAdmin()` — same shape as `departments.ts`'s helper, but decodes the JWT via `parseJwtPayload(session.access_token)` instead of raw `atob` (CLAUDE.md 2026-06-26). Rejects any role other than `admin`/`safety_manager`.
- `getSopAgentMetadata(sopId)` — org-scoped read of `sop_agent_metadata`, mapped to a `SopAgentMetadataView` (summary/tags/entities/assessment/links/`hasEmbedding`/last-synthesis status+error). `.eq('organisation_id', ctx.organisationId)` explicit even though RLS also gates it.
- `getBlockAgentMetadata(sopId)` — org-scoped read of `block_agent_metadata` filtered by `sop_id`, mapped so each row's `junctionId` = `block_id` (the `sop_section_blocks` junction id, D-02).
- `getAgentDashboardData()` — up to 50 pending proposals + up to 50 recent memory rows for the caller's org, for Plan 08's dashboard.
- `approveProposalAction(proposalId)` / `declineProposalAction(proposalId)` — verify admin ctx, then delegate to `approveProposal`/`declineProposal` from `agent-proposals.ts` (org self-enforced there and here); return the discriminated `{ success: true } | { error }` union, never throw.
- Every export is async; `'use server'` file has zero sync/pure value exports (CLAUDE.md 2026-06-27).

**Task 2 — agentview toggle + read-only panel:**
- `blueprint-theme.css`: added `--ai: #8b5cf6` to `:root`, plus `.agentpanel`/`.ameta`/`.agentbanner` classes lifted (near-verbatim) from `sketches/sop-builder-redesign/index.html`, re-scoped to `.agent-layer-root.agentview` (a class BuilderClient owns) instead of global `body.agentview`.
- `AgentPanel.tsx` — SOP-level panel: summary, tags as static chips, entities/links stringified read-only, embedding presence badge, last-synthesis status. Also renders the SOP's pending proposals with Approve/Decline buttons — the *only* interactive affordance on the whole surface (D-10).
- `AgentBlockMeta.tsx` — flat list of per-block `.ameta` rows, one per `block_agent_metadata` row, keyed by `junctionId` (D-02): id, tags, entities, embedding badge.
- `AgentBanner.tsx` — passive sticky banner, no handlers.
- `BuilderClient.tsx` — `agentview` boolean state + `⚇ Agent layer` toggle button in the header (next to `RerunReviewerButton`/SAVED pill); toggling applies the `agentview` class to a new `agent-layer-root` wrapper on the component's own root div; a `useEffect` gated on `agentview` fetches SOP + block agent metadata + org proposals (filtered to this SOP) only while the toggle is on. Approve/decline handlers optimistically remove the proposal from local state, then call the server action.

**Test:** `tests/phase26.5/agent-panel-readonly.spec.ts` made LIVE (was a Wave-0 stub): a real `react-dom/server` render via `scripts/agent-panel-check.tsx` (tsx subprocess — same pattern as `render-parity-check.tsx`/`ai-overlay-check.tsx`, since Playwright's own JSX transform can't render genuine React) asserts the rendered markup of `AgentPanel`/`AgentBlockMeta`/`AgentBanner` contains zero `<input>`/`<textarea>`/`contentEditable`/`onChange`, that `AgentBlockMeta` renders/keys by `junctionId`, and that `AgentPanel`'s only buttons are the sanctioned approve/decline. A second test asserts the same source-contract absence directly on the 3 component files, a third pins `AgentBlockMeta`'s `key={row.junctionId}`, and a fourth asserts `BuilderClient`'s toggle `onClick` actually calls `setAgentview` (not an empty handler — the 21.6 dead-affordance trap).
