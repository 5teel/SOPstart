# Phase 26.5 Plan 02: Agent Metadata Schema Summary

**One-liner:** Migration 00040 ships all 5 agent-layer tables + pgvector + HNSW + the `match_sop_agent_metadata` similarity RPC in one additive push, verified live on the DB via Management API `to_regclass`/`pg_extension`/`pg_proc` — zero cross-table RLS policy, byte-identical security shape to 00038/00039.

## What Was Built

**Task 1:** `supabase/migrations/00040_agent_metadata_schema.sql` — `create extension if not exists vector;` followed by 5 tables, each with the exact 00038/00039 shape (`organisation_id` direct-column RLS SELECT via `current_organisation_id()`, zero cross-table policy reference, no authenticated write policy, indexed FKs, closing `comment on table`):
- `sop_agent_metadata` — summary/tags/entities/embedding/assessment/links/last_synthesis_status+error, unique index on `sop_id`, HNSW index on `embedding`
- `block_agent_metadata` — keyed by `sop_section_blocks.id` (D-02 junction identity), unique index on `block_id`, HNSW index on `embedding`
- `agent_memory` — append-only per-SOP/org-wide observations (`scope` check constraint, nullable `sop_id` for org-wide rows)
- `agent_learning_proposals` — sibling table to `ai_field_proposals` with an `evidence jsonb` column, always-pending status machine (`pending`/`applied`/`rejected`)
- `sop_voice_qa_log` — voice Q&A transcript persistence (question/answer/citations), closing the RESEARCH Pitfall 1 gap that the voice route previously had no write path at all
- `match_sop_agent_metadata(p_organisation_id, query_embedding, match_count)` — `language sql stable security definer`, wraps `embedding <=> query_embedding`, filters `organisation_id = p_organisation_id` inside the body (self-enforced, since SECURITY DEFINER bypasses RLS)

Hand-extended `src/types/database.types.ts` with Row/Insert/Update + Relationships for all 5 tables, matching the `sop_image_annotations` structure already in the file. Made `tests/phase26.5/schema-contract.spec.ts` live — replaced the Wave-0 stub body with 8 real assertions (extension present, all 5 tables present, exactly-one-SELECT-policy-per-table using `current_organisation_id()`, zero `from public.sops` in any policy body, no INSERT/UPDATE/DELETE policy anywhere, `block_agent_metadata` FK to `sop_section_blocks`, 2 HNSW indexes, RPC shape).

**Task 2 [BLOCKING]:** Ran `supabase db push` (SUCCESS) and created `scripts/apply-phase26.5-migration.mjs` (modeled on `apply-phase23-migration.mjs`) — issues `NOTIFY pgrst, 'reload schema'` then verifies all 5 tables + `vector` extension + `match_sop_agent_metadata` via the Supabase Management API's raw-SQL endpoint (`to_regclass`/`pg_extension`/`pg_proc`), which bypasses the PostgREST schema cache entirely (per CLAUDE.md 2026-06-15 learning). Each assertion retries once after an explicit cache reload before reporting a genuine failure, distinguishing `PGRST205` cache staleness from real `42P01` absence. Also asserts `SELECT 1 FROM sops` returns without `42P17` recursion.
