# Phase 26.5 Plan 08: Org Agent Dashboard Summary

**One-liner:** `/admin/agent` SSR route (admin/safety_manager-gated) renders an evidence-backed proposals queue with working Approve/Decline plus a recent-activity feed, and the living pathways map (`journeys.ts` + `uat/tests.ts`) now covers the new route and the builder's agentview toggle.

## What Was Built

**Task 1 — `/admin/agent` dashboard route:**
- `page.tsx` — SSR Server Component, exact auth-guard shape as `/admin/departments/page.tsx`: `getUser()` → redirect `/login` if none; `organisation_members` role fetch → redirect `/dashboard` if not `admin`/`safety_manager` (D-09). Fetches `getAgentDashboardData()` (Plan 07) and passes `{ pendingProposals, recentMemory }` plus any fetch error to the client.
- `AgentDashboardClient.tsx` — client component with two sections, both styled with the `.agentpanel`/`.arow`/`.ak`/`.av` purple `--ai` classes lifted from the sketch (blueprint-theme.css, same visual identity as Plan 07's builder `AgentPanel`):
  - **Primary — proposals queue**: each row shows `kind`, `description`, and its structured `evidence` (JSON-stringified); Approve/Decline buttons call `approveProposalAction(id)`/`declineProposalAction(id)` via `useTransition`, and on `{success:true}` the row is filtered out of local `proposals` state — the row genuinely leaves the queue (not a dead affordance, CLAUDE.md 2026-06-05). Errors surface in an alert banner, the row stays in the queue.
  - **Secondary — recent activity feed**: read-only list of `recentMemory` rows (scope, observation, signal source) — the D-14 payoff, proving the layer is alive.
  - No cross-SOP graph visualisation anywhere in either file (D-11/D-13 scope held).
- `tests/phase26.5/agent-dashboard.spec.ts` — replaced the Wave-0 `test.skip`/`test.fixme` stub with 4 live source-contract tests: guard + `getAgentDashboardData` call; Approve/Decline wired to the two proposal actions AND `setProposals(...filter...)` proving the row-removal behaviour; proposals render evidence + activity feed present; no `react-konva`/`Konva`/`FlowGraphCanvas`/`<canvas` anywhere in either file.

**Task 2 — living pathways map:**
- `journeys.ts` — new `agent-layer` Journey in the `Refine & publish` group: admin opens the builder → toggles `⚇ Agent layer` (`route: '/admin/sops/builder/[sopId]'`) → opens the org dashboard (`route: '/admin/agent'`) → reviews the queue/feed → approves or declines. Both new routes are real, so `/pathways` "All screens" now shows 0 not-mapped for `/admin/agent`.
- `uat/tests.ts` — new `agent-layer-dashboard` entry (category "Phase 26.5 — Agent Metadata Layer") asking the team whether the read-only panel felt read-only, evidence was clear, approve/decline worked, and the layer felt useful rather than intrusive.
