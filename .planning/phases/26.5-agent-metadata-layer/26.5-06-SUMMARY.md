# Phase 26.5 Plan 06: Scheduled Synthesis Sweep Summary

**One-liner:** Cron-invoked `POST /api/agent-layer/synthesis-sweep` catches up SOPs whose signals accrued since their last synthesis — authenticated by a constant-time `CRON_SECRET` bearer compare that fails closed, failing fast with a specific 503 when `VOYAGE_API_KEY` is unset, batch-capped, with every write org-scoped via the shared `synthesizeSop` pipeline.

## What Was Built

**Task 2 — `src/app/api/agent-layer/synthesis-sweep/route.ts` (POST):**
- **Auth (T-26.5-06-01):** reads the `authorization` header, strips `Bearer `, compares against `process.env.CRON_SECRET` with `crypto.timingSafeEqual` (length checked first — the API throws on mismatched lengths). Missing/mismatched → 401 immediately. **Unset `CRON_SECRET` fails closed** (`if (!secret) return false`). Zero `auth.getUser()`/`auth.getSession()` — this is a machine endpoint, not a user route.
- **Key fail-fast (T-26.5-06-04):** if `VOYAGE_API_KEY` is unset, returns `503 { error: 'voyage_api_key_missing' }` before touching the DB — the specific-code-not-generic-SDK-exception resolution of RESEARCH Open Question 1 (Deepgram precedent, twice-shipped-broken).
- **Sweep body (D-14):** `findStaleSops()` selects published SOPs joined to `sop_agent_metadata(regenerated_at)` (cap 100 evaluated); a SOP is stale if it has no metadata row yet, or `hasNewerSignal()` finds a `sop_completions` (`submitted_at`), `sop_voice_qa_log` (`created_at`), or `parse_jobs` (`updated_at`) row newer than `regenerated_at` — every probe filtered by BOTH `sop_id` and `organisation_id`. Up to `MAX_SOPS_PER_SWEEP = 20` stale SOPs get `await synthesizeSop(sopId, organisationId)` (T-26.5-06-03 batch cap; Railway Cron min interval 5 min, each run stays short). Returns `{ processed, skipped }`.
- **Org-scope (T-26.5-06-02):** all writes happen inside `synthesizeSop`, which self-enforces org-scope on every path (Plan 04); the sweep passes each SOP's own `organisation_id` from the org-filtered candidate query.
- Header comment documents the Railway Cron deployment model (separate one-shot process with the shared secret — never an in-process `setInterval`, which would violate the single-process deploy constraint).

**`tests/phase26.5/synthesis-sweep-auth.spec.ts` made LIVE** (was a Wave-0 skip-when-absent stub): 7 source-contract tests — 401 on missing/invalid secret, fail-closed regex (`if (!secret) return false`), `timingSafeEqual` present, no cookie-session auth calls, specific 503 + `VOYAGE_API_KEY`, `synthesizeSop` + `MAX_SOPS_PER_SWEEP` batch cap, and >2 `organisation_id` filters across the signal probes.
