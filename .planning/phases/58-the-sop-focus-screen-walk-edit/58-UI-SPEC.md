# Phase 58 — UI Design Contract

> Visual and interaction contract for the SOP focus screen (Walk + Edit). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Governing sources: `58-CONTEXT.md` (D-01..D-14, locked), `one-screen-site.md` § "The focus rule" (non-negotiable), `src/styles/blueprint-theme.css` (the only place tokens live).

## Frame (both modes)

One frame, five states. `data-testid="focus-screen"` on the root; `data-mode="browse | walk | review | edit | parsing"` and `data-version-state="live | draft | superseded"`.

```
┌ top bar (min-h-tap, border-b border-ink-200, bg-paper) ───────────────────────┐
│ ← Back   SOP title (truncate)          [Walk | Edit] admin only   Saved       │
├ rail w-75 (300px) ─┬ column (flex-1, scrolls) ────────────────────────────────┤
│ bg-paper-2         │   max-w-205 (820px), centred, px-4 lg:px-8 py-8          │
│ border-r ink-200   │   progress → kind chip → STEP TEXT → tip → photo → button│
│ sections + steps   │                                                          │
│ ─ This SOP ─       ├──────────────────────────────────────────────────────────┤
│ (pinned bottom)    │ bottom bar (edit: Checked n of N + Publish)              │
└────────────────────┴──────────────────────────────────────────────────────────┘
```

| Rule | Value |
|------|-------|
| Layout | `flex`: rail `w-75 shrink-0`, column `min-w-0 flex-1`. Page does not scroll; rail and column scroll independently. Never `grid-cols-[300px…]` or `w-[300px]` (lint) |
| Column | inner wrapper `mx-auto w-full max-w-205` |
| Opt-out | `(protected)/layout.tsx` must NOT render `BackToSite` / bottom tab bar / account control on focus routes; the frame renders its own top bar |
| Banned on screen | map, list, inbox count, notification bell, account menu, toasts over a step, any badge in the top bar. A badge in the focus bar is a defect |
| Top bar contents | Back (`ArrowLeft` + "Back", `min-h-tap`), SOP title (text-reading semibold, truncate), right cluster: admin-only Walk ⇄ Edit switch, edit-only save pill. Nothing else |
| Back / Esc | Back button = Esc. `history.back()` only when referrer is the one screen, else `router.push(from ?? '/')` where `from` is the `?from=<place-token>` (57 D-11). Esc order: close open dialog/popover/rail sheet → leave a text field being edited → Back. Never a "discard changes?" prompt: walk progress is server-saved (D-09), editor autosaves; Back waits up to 3 s for a pending save to flush |
| Redirect | legacy `/sops/[id]?tab=…`, `/admin/sops/builder/[id]`, `/admin/sops/[id]/versions` 307 in the proxy (never a client effect) |
| Step changes | `useState` + `history.replaceState` for `?step=`; never `router.push` (CLAUDE.md 2026-05-13). Focus moves to the step text (`tabIndex={-1}`) after each change; `aria-live="polite"` announces "Step 7 of 24" |
| Motion | none required; no slide/fade between steps. Respect `prefers-reduced-motion` (parsing pulse becomes static) |

### Phone / narrow (below 1024 px — CSS only, 57 D-21; frame always renders)

| Element | Behaviour |
|---------|-----------|
| Rail | Collapses to a full-screen left sheet (`max-lg:fixed max-lg:inset-0 max-lg:z-40`, `bg-paper-2`), closed by default. Opened by a top-bar button "Steps · 7 of 24" (`List` icon, `min-h-tap`). Picking a row closes it. Esc / "Close" (`X`, `min-h-tap`) closes it. A scrim is unnecessary (full-screen) |
| Top bar | Back becomes icon + "Back"; title truncates; Walk ⇄ Edit switch moves to the top of the rail sheet below 640 px |
| Walk action area | Photo button + primary button become a sticky bottom dock (`sticky bottom-0 border-t border-ink-200 bg-paper p-4`, safe-area padding). At lg+ they sit inline below the step content |
| Column padding | `px-4` (phone) → `lg:px-8` |
| Step text | stays `text-step` (28 px) — wraps; never shrink below it on phone |
| Edit on phone | works through the same frame (rail sheet + sticky bottom bar) but is not separately designed (deferred) |

## Walk — states and anatomy

Walk order (D-07): a "Before you start" group (all hazard + PPE steps, wherever they sit in the source), then every section's steps in order. One completion per SOP.

### Browse state (no completion exists)

Entry: "Show me", any SOP row click that is not Walk/Edit, an admin's Walk, an earlier version.

| Zone | Contents |
|------|----------|
| Column top | SOP summary card: step count + time estimate ("24 steps · about 20 min" — only if estimates exist), `RelBadge` "Updated" + line "Updated since you last walked it" when D-12 applies |
| Resume card (only if an in-progress completion exists) | "Resume where you left off (step 7 of 24)" primary (`min-h-tap-glove`) + "Start over" ghost (confirm — see Destructive) |
| Body | every step listed in walk order under its section heading: kind chip, step text (`text-reading`), tip, standards labels, images. Read-only cards (`bg-paper-1 border border-ink-200 rounded-lg border-l-4` in kind colour) |
| Bottom bar (sticky, always reachable) | "Start walking" primary, `min-h-tap-glove`. Hidden for superseded versions |
| Rail | all rows clickable → scrolls the column to that step (no completion) |
| Superseded (D-14) | neutral banner top of column: `History` icon, "v2 — superseded. Workers are on v4." + link "Go to the current version". Top-bar chip "v2 — superseded". No Start walking |

### Walking (one step alone)

Top to bottom inside `max-w-205`, `gap-6`:

| # | Element | Spec |
|---|---------|------|
| 1 | Progress | `h-1 rounded-full bg-ink-100`, fill `bg-accent-step`; label `mono text-meta text-ink-500` "Step 7 of 24" (hazard/PPE count as steps) |
| 2 | Section label | `mono text-meta uppercase text-ink-500`: section title, or "Before you start" |
| 3 | Kind chip | `rounded mono text-meta uppercase px-2 py-1`, kind colour text on `/10` tint. Labels: **Hazard · PPE · Step · Check**. Standards labels sit beside it |
| 4 | Step text | `text-step font-semibold text-ink-900`, `max-w-full` |
| 5 | Hazard / PPE card | wraps 3–4: `rounded-lg border border-accent-hazard/40 bg-accent-hazard/10 border-l-4 p-4` (PPE uses `accent-decision`). Icon: `AlertTriangle` (hazard) / `ShieldCheck` (PPE) |
| 6 | Tip | neutral callout `rounded-lg bg-paper-2 border border-ink-200 p-4`, `Lightbulb` `text-ink-500`, label "Tip", body `text-reading` |
| 7 | Step images | `rounded-lg` full column width, `max-h` capped; no annotation tooling for workers |
| 8 | Photo (only if `photo_required`) | secondary button `min-h-tap-glove w-full rounded-lg border border-ink-300 bg-paper-1`, `Camera` icon, "Take a photo". After capture: 72 px thumbnail + "Retake". Uploads immediately via `useStepPhotos` → `getPhotoUploadUrl` |
| 9 | Primary button | `min-h-tap-glove w-full rounded-lg bg-ink-900 text-paper text-reading font-semibold`. Disabled = `bg-ink-300 text-ink-500` + `aria-disabled` + helper line `text-ui text-ink-500` |
| 10 | Previous | quiet ghost under the primary, `min-h-tap text-ui text-ink-700`, "← Previous step". Absent on step 1 |

Primary labels by kind (contract wording):

| Kind | Label |
|------|-------|
| Hazard | I understand — continue |
| PPE | I'm wearing it — continue |
| Step | Done — next step |
| Check | Confirmed — next step |
| Last step | Done — review (any kind: replaces the label above) |

Rail rows (walk): `min-h-tap`, kind dot + one-line truncated text.

| Row state | Look | Click |
|-----------|------|-------|
| Done | `Check` `text-accent-ok`, `text-ink-700` | revisit; photo can be retaken |
| Current | `border-l-4 border-accent-step bg-paper-1 font-semibold` | — |
| Ahead (default, D-08) | `Lock` `text-ink-400`, `text-ink-400`, `aria-disabled` | not clickable |
| Ahead (jump-ahead ON) | normal `text-ink-700`; unacknowledged hazard/PPE rows show a hollow kind dot | clickable |

Keys (desktop): Enter = primary when enabled; ← = previous; Esc = Back. Hazard/PPE can never be skipped, including with jump-ahead ON (blocked at Send, below).

Server writes (D-09): each ack, each step done, each photo writes to the in-progress completion before advancing. If the write fails the step does not advance (online-only app).

### Review and confirm (D-10)

| Zone | Spec |
|------|------|
| Headline | "Ready to send?" `text-step font-semibold`; sub `text-reading text-ink-700` "Look over what you did. Once you send it, your supervisor signs it off." |

| List | grouped by section; each row `min-h-tap` (`min-h-tap-row` with a photo): `Check` `text-accent-ok`, step text one line, mono "Acknowledged" on hazard/PPE, 72 px photo thumb. Row click returns to that step (then back to review) |

| Sent | centred `CheckCircle` (`size-12 text-accent-ok`), "Sent for sign-off" (`text-step`), "Your supervisor will check it." (`text-reading`), one button "Back to the site" (`min-h-tap-glove`, = Back). No further actions |

## Edit — states and anatomy

Same frame. Steps stay grouped under their source sections (not walk order). The column IS the worker document edited in place: click text to change it.

### Column, top to bottom

| # | Element | Spec |
|---|---------|------|
| 1 | Version slot (fixed height, reserved so nothing shifts) | `text-ui` neutral strip: published SOP → "Editing v4 — v3 is live"; never published → "Draft — not published yet"; just published → "Published v4 · logged in the decision ledger" |
| 2 | AI check banner | `rounded-lg border border-[--tint-ai-border] bg-[--tint-ai-bg] p-4` via the token pair (utility form per lint), `Sparkles` `text-ai`. States below |
| 3 | Section | header: `mono text-meta text-ink-500` "01", title (`text-reading font-semibold`, click-to-edit), hairline `h-px flex-1 bg-ink-100`, `⋯` menu button `min-h-tap` |
| 4 | Step card | `rounded-lg border border-ink-200 bg-paper-1 p-4 border-l-4` (kind colour), gap-4 between cards |
| 5 | "Add a step" | persistent dashed row at end of each section: `min-h-tap rounded border border-dashed border-ink-300 text-ui text-ink-500`, hover/focus `text-accent-step border-accent-step`. Hairline "＋" between steps appears on hover/focus-within at lg+ and is always visible below lg |
| 6 | "Add a section" | same dashed row after the last section |

Step card contents: kind select (chip-shaped button → menu Hazard / PPE / Step / Check) · step text (`InlineText`, `text-reading`) · tip (collapsed "Add a tip" ghost → textarea labelled "Tip") · switch "Needs a photo" · images row (72 px thumbs, each with Annotate / Remove, + "Add a photo") · standards labels + "+ Standard" · `⋯` menu (Move up, Move down, Delete step) · **tick** at the card foot: checkbox `min-h-tap`, label "I have checked this". Ticked = `Check` `text-accent-ok` + label "Checked". No tick-all control anywhere.

Default behaviour (Claude's default, not user-decided): editing a step's text, kind, tip or photo flag clears its tick and shows mono "Edited — check it again". Reordering and standards changes do not.

Section `⋯` menu: Rename, Move up, Move down, Standards…, Delete section. Menus are keyboard-operable; reordering is by Move up/down (no drag this phase).

### AI check banner states

| State | Copy / controls |
|-------|-----------------|
| Not run | "Run the AI check" button (`min-h-tap`, `Sparkles`) + "It reads every step and flags anything unclear or unsafe." |

### Bottom bar (sticky, `min-h-tap-row`, `bg-paper-1 border-t border-ink-200`)

Left: "Checked 12 of 24 steps" (`text-ui font-semibold`) + `h-1` bar (`bg-accent-ok`). Middle (when blocked): `text-ui text-ink-500` reasons, e.g. "12 steps still to check · 2 AI findings open" / "Add at least one step". Right: **Publish v4** (`min-h-tap`, `bg-accent-signoff text-white` when enabled; `bg-ink-300 text-ink-500` + `aria-disabled` when not). Enabled only when every step is ticked AND every finding is cleared AND ≥1 step. Press opens the publish dialog (below).

### Left rail (edit)

Scrolling list: sections (`mono text-meta uppercase`) with their steps (kind dot, one-line text, right-aligned state: hollow circle unticked / `Check` `text-accent-ok` ticked / violet dot flagged). Click scrolls and focuses the step. "＋ Add section" row at the bottom of the list.

**"This SOP"** pinned under the list (`border-t border-ink-200`, collapsible; collapsed summary "v4 · Press 3 · 2 standards"):

| Row | Spec |
|-----|------|
| Version | "Editing v4 — v3 is live"; "3 earlier versions" → inline list (v3 live · v2 · v1); click opens that version in browse state, read-only, badged "v2 — superseded" (D-14) |
| Machine | name, or "Whole site"; select to change |
| Objective | dashed-border metadata box (`rounded-lg border border-dashed border-ink-300 p-2 text-ui`), click to edit, empty = "Add an objective" |
| Standards | `StandardLabels` + "+ Standard" popover (existing standards, checkboxes; SOP level) |
| Let workers jump ahead | switch, default OFF. Hint: "Off: workers go back only, in order. On: they can open any step, but every hazard, PPE and photo is still needed before sending." Admin write, per SOP (D-08) |

### Autosave pill (top bar, edit only)

`mono text-meta`: "Saving…" · "Saved" (`text-ink-500`) · "Not saved — retrying" (`text-accent-escalate`). After 3 failed retries a strip appears above the column: "Your last change didn't save. Keep this page open and we'll keep trying."

### Annotation (D-03)

Add a photo → upload; Annotate opens the existing Konva tool (`builder-v2/visual/`) in a full-screen dark-chrome overlay (`steel-900`, the sole dark surface). Esc closes (saves nothing unless "Save"). Lazy, admin seam only — never in the worker bundle.

### Publish dialog (focused popup; screen recessed)

`rounded-2xl bg-paper-1 p-6`, scrim `bg-ink-900/40`. Title "Publish v4?" Body "Workers get v4 the next time they open this SOP. v3 stays on record." Buttons: "Publish v4" (`bg-accent-signoff`) · "Not yet" (ghost). Success writes the ledger row and updates the version slot; no redirect.

### Empty (blank SOP)

Centred, `py-16`: heading "Nothing here yet" (`text-reading font-semibold`), body "Add your first section, then write the steps a worker follows." button "Add a section" (`min-h-tap`). The bottom bar shows "Checked 0 of 0" with Publish disabled ("Add at least one step").
