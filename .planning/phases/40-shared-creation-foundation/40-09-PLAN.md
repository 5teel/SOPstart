Give every admin creation route the same page shell and navigation, so Phase 41's nav change is one edit in one file.

  <action>
Create `src/components/admin/AdminPageShell.tsx`. It must be importable from **both** server components (`upload/page.tsx`, `new/blank/page.tsx`, `new/ai/page.tsx`) and client components (`versions/page.tsx` and `PipelineProgressClient.tsx` are both `'use client'`). Do not mark it `'use client'` — `AdminNav` is server-renderable and its only client sliver is `NavPendingSpinner`, which already carries its own directive. A non-directive component composes into both trees.

Props:
- `active: AdminNavKey` — passed straight through to `<AdminNav active={...} />`
- `title: string`
- `badge?: string` — the `pill` label (`new/ai/page.tsx` uses `AI DRAFT`)
- `description?: ReactNode`
- `backLink?: { href: string; label: string; ariaLabel?: string }` — **the contextual slot that makes DUP-04 safe.** RESEARCH Pitfall 5: `/admin/sops/[sopId]/versions` and the pipeline page link back to a specific SOP's builder, which `AdminNav` cannot express. This slot preserves that link *alongside* the section nav rather than replacing it. When omitted, no back-link renders — because `AdminNav` already carries the route back to the library, a route whose only back-link was "Back to library" needs no slot at all, and that redundant link is deleted rather than migrated.
- `mono?: boolean` — apply the `mono` class to the heading (the AI page's idiom)
- `children: ReactNode`
- `contentClassName?: string` — for the two routes whose content column is not the standard `max-w-2xl`

Render order: `<AdminNav active={active} />`, then the header row (badge pill, heading, description on the left; the contextual back-link on the right when supplied), then `{children}`. Use the container classes from `new/sops/new/page.tsx` as the canonical layout and the existing utility classes verbatim (`pill`, `mono`, `text-[var(--ink-900)]`, `text-[var(--ink-500)]`) — this is consolidation, not a restyle. Reference no CSS custom property that is not already declared: `tests/lint/no-undefined-css-tokens.spec.ts` fails CI on a fallback-less `var(--x)` that no stylesheet declares (CLAUDE.md [2026-07-14], and a token bug renders wrong while failing nothing else).

Do not add auth logic. `AdminNav`'s own header comment states it is presentation only and does not replace any per-page role gate (threat model T-30-03-01); the same holds here — every page keeps its own `getSessionContext` guard and its own `redirect('/dashboard')`.
