## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin browser -> `/api/sops/ai-prompt` | The picker's `title`, `categorySlug`, `departmentIds`, `allDepartments` cross here as untrusted input |
| Client picker -> `assignSopDepartments` | Department visibility is an access-control decision; the write path is the Phase 33 grant-backed action |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-08-01 | Elevation of Privilege | client-supplied `departmentIds` granting visibility to another org's departments | mitigate | D-11 keeps every write on `assignSopDepartments`, which already filters the supplied ids to the caller's org (Phase 25/33 fix for the CLAUDE.md [2026-06-15] service-role class). `SopMetadataFields` is presentational and cannot write; the acceptance criteria assert zero `.from('sop_departments')` anywhere in scope |
| T-40-08-02 | Tampering | arbitrary `categorySlug` string reaching a category-keyed settings lookup | mitigate | `/api/sops/ai-prompt` and `createSopFromWizard` gate on `isValidCategorySlug` (plan 40-04); the client `<select>` renders only `SOP_CATEGORIES` values but is not the control |
| T-40-08-03 | Tampering | client-supplied `title` overriding the AI-derived title | accept | Bounded by the Zod `max(200)` on `aiPromptSchema.title`; org-scoped free text on a row the caller is authorised to create, stored and never evaluated |
| T-40-08-04 | Information Disclosure | deleting the `DISTINCT sops.category` query | mitigate | Removing it is a net reduction in exposure — it previously read up to 500 rows of an org's SOP categories to populate a dropdown; the fixed vocabulary needs no query at all |
| T-40-08-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed; RESEARCH.md records the phase as install-free |
</threat_model>
