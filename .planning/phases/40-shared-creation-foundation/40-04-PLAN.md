<objective>
Establish the single SOP-category vocabulary, add the single column that holds it, push that column to the live database, and repoint every write path onto it.

Purpose: DAT-01 / D-01 / D-03 — a SOP's category currently resolves to two columns with two vocabularies: `sops.category` (free text, written by five API routes) and `sops.category_tag` (a `block_categories` slug, written by the wizard). Both retire onto one new `sops.category_slug` column backed by one fixed seed. This plan does the additive half (new column, new vocabulary, writes repointed); plan 40-05 repoints the readers and plan 40-06 backfills and retires the old data.

Output: `src/lib/sop-categories.ts`, migration `00058`, the column live on prod, and six write sites emitting `category_slug`.
</objective>
