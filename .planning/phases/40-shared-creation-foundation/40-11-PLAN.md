<objective>
Close verification GAP 3 (DAT-01): `cloneSopAsDraft` — the shared implementation behind both "Edit into new version" and `restoreVersionAsNew` ("Restore") — neither selects nor writes `category_slug`, so every SOP put through those two everyday admin actions silently loses its category.

Purpose: this is not cosmetic metadata loss. 40-VERIFICATION.md traces the cascade: the cadence lookup falls back to the 12-month default, `ensureSopCollectionsForOrg` skips the collection join, and the publish route's approval-chain gate never matches — a chain-gated category silently loses its approval requirement on the clone. That is a governance hole. The sibling function `uploadNewVersion` in the same file was correctly patched in plan 40-07; the insert this plan fixes even carries the comment "this insert is an explicit field list, so any future per-SOP column must be added here too".

Per CLAUDE.md [2026-07-29] (data-keyed sweeps) the fix must NOT be keyed on the two named functions. The guard is keyed on the DATA: every write to the `sops` table under `src/`.

Output: category survives every version-creation path, and the guard is a table-write census that fails on any new, unclassified `sops` write site.
</objective>
