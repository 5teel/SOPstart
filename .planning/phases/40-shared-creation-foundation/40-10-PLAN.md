<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser file picker -> `validateIntakeFile` | Untrusted file; client-side gate only, advisory |
| Browser -> `createUploadSession` (`uploadFileSchema`) | The authoritative server-side type/size gate; a client can post any `{name,size,type}` triple |
| Uploaded bytes -> parser libraries (mammoth / unpdf / officeparser) | Macro-enabled Office formats must never reach a parser |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-10-01 | Tampering | macro-enabled workbook renamed to `.xlsx` reaching a parser | mitigate | `validateIntakeFile`'s blocked-macro branch now checks `BLOCKED_MIME_TYPES` as well as `BLOCKED_EXTENSIONS`; the server `uploadFileSchema.refine` keeps its independent `BLOCKED_MIME_TYPES` exclusion (both now read the same list) |
| T-40-10-02 | Spoofing | client posts a `type` string the shared module never accepted, bypassing the client validator | mitigate | The server schema is the gate and now derives from the same `ACCEPTED_MIME_TYPES`; `getSourceFileType` still throws on unknown types rather than defaulting |
| T-40-10-03 | Denial of Service | oversized document accepted because the size limit drifted between client and server | mitigate | `MAX_FILE_SIZE` / `MAX_VIDEO_FILE_SIZE` are imported from the one module; the single-source sweep fails if either is re-declared elsewhere |
| T-40-10-04 | Repudiation | a file the UI advertised as supported is rejected server-side, leaving the user with a generic error | mitigate | Root cause of GAP 1; closed by derivation plus the runnable parity harness that exercises the real schema for every advertised type |
| T-40-10-SC | Tampering | npm/pip/cargo installs | mitigate | No packages installed — `tsx` and `zod` are already dependencies; RESEARCH.md records the phase as install-free |
