Build the two overlay controls of the worker home that sit beside the scene: the Now card (the single next procedure) and the ask bar (live filter + voice entry).

Purpose: HOM-03 (Now card with Walk it and Show me) and HOM-05 (ask bar that highlights as the worker types and is the entry to the existing voice Q&A) exist as tested components before 52-04 composes them.

Choices stated per D-13 / research Q1 (resolved):
- The mic opens `WalkthroughVoiceModal` directly, imported with `next/dynamic({ ssr:false })` INSIDE the plant module (Next dedupes the chunk with the walkthrough's own dynamic import; it never enters `/sops`'s base bundle). No new voice path. It is scoped to one `voiceSopId` the composer passes (the open panel's first to-do SOP, else the Now card's SOP); with no SOP in scope the mic is disabled. The modal's step-navigation intents ("next", "back") have no walkthrough to drive here, so they are passed no-op handlers and `currentStepText=""` (no read-aloud on open); questions go to the existing `/api/voice/query` grounded in that SOP.
- The ask bar INPUT is rendered in the plant's on-scene toolbar (the sketch 007 layout: department chips + ask bar across the top of the scene) and is bound to the page's existing `query` / `setQuery` — the same state the toolbar search box uses. 52-04 hides the page toolbar's input while the plant is showing, so exactly one search input is ever on screen and there is still one query state. That is how "the existing toolbar search input becomes the ask bar on the plant view" is realised without shipping the mic in the page's base bundle (D-14).
- "~min" is the sum of the SOP's cached steps' `time_estimate_minutes` (Dexie `sections` by `sop_id` → `steps` by `section_id`), shown only when > 0. No SOP-level duration field exists; every Now-card SOP is an assigned (cached) one.
