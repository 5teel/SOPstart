Choices made here (Claude's discretion, stated for Simon):
- Area (R8): machine's department → first `sop_departments` tag (by name) → `site-wide`; areas exist only when they hold a visible published SOP. Area order: by name, Site-wide last; colour `var(--area-N)` cycling 1..8 by that order (Open Q8 default).
- Type (R3): `emergency` slug → Emergency; `quality` slug → Inspection; machine-linked (a `sop_machines` row or `placement 'machine'`) → Machine; else Process. "Order of operations" is not derived (deferred until a `sop_type` field exists).
- Object kind: first linked machine name keywords (tank|vat|silo → tank; conveyor|lehr|line|belt → conveyor; forklift|truck → forklift; rack|shelv → rack; bench|lab → bench; else machine); not machine-linked → board (the noticeboard).
- Recent (ADR-0002, no table, no job): per-device localStorage `sopstart-recent:<userId>` merged with own `sop_walks.updated_at` and `sop_completions.submitted_at` by lineage root, top 4. Most used: own non-rejected completions per lineage root, top 3, "done N×".
- Address: `?s=` sops (default, omitted) | record | training | signoffs | people | manage; `sop`, `area` only in sops; `tab` only in signoffs (inbox|requests|decisions) and people (people|access); `pin` only with people+access; `view=site` only in manage. A focus `from` token is the home query string itself (`s=signoffs`, `sop=<uuid>`); a token without `=` is a legacy place token.

Output: six plain modules (no directive, no Next imports, no Supabase) and three specs.
