# Phase 26 — UI Design Contract

> Visual and interaction contract for the FULL BESPOKE inline SOP builder that replaces Puck.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Design tokens are the **sketch-findings-SOPstart** paper/ink system — NOT invented here.
> Interaction model is the validated `sketches/sop-builder-redesign/index.html`.
> This spec adds the contracts the sketch does NOT cover: the 16 field editors, the Konva
> annotation editor, per-block AI-flag/verify overlays, convert-provenance affordances, and responsive.

---

## Scope of this contract

| Covered by the validated sketch (LOCKED — encoded, not re-designed) | Added by THIS spec (the sketch does not cover) |

previews it; this phase must NOT render it and must NOT block it. Only the contract note in §Agent-Layer Contract applies.

## Spacing Scale

Declared values (multiples of 4). The admin builder is desktop-first; card padding follows the sketch.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/tool-button gaps, block-tools row gap, inline chip padding-y |
| sm | 8px | Compact spacing; pill padding-x; add-divider height/2 |
| md | 12px | Block inner padding-x, picker row padding, rail item padding — the builder's default unit |
| — | 15–16px | **Block card padding** (`.blk` 15px 16px) — from the validated sketch; keep verbatim |
| lg | 24px | Section/card padding on desktop reading surfaces |
| xl | 30–32px | Gap between sections (`.sec` margin-bottom 30px); canvas padding-x |
| 2xl | 48px | On-ramp vertical rhythm |
| 3xl | 64px | Canvas bottom padding (90px scroll runway is an intentional exception for the last-block inserter) |

**Exceptions (declared, non-blocking):**
1. **20px grid-paper canvas unit.** The edit canvas background is a 20px grid (`background-size:20px 20px`). This is the engineering-drawing metaphor, not a layout spacing token — block/section positions still reflow on the 4-pt scale; only the backdrop is 20px.
2. **Konva pixel-space.** The diagram-annotation editor and `DiagramHotspotBlock` callout x/y are **free pixel coordinates** in the image's natural dimension space — the ONLY freeform-positioning surface (D-03). Not on any spacing scale by design.
3. **Rail width 220px, doc max-width 680px, phone frame 390px** — fixed layout constants from the sketch.

## Typography

The system is LOCKED by sketch-findings (an established, validated scale — not a greenfield 4-size pick).
Declared canonical roles below. **Flag (non-blocking):** this exceeds the template's "3–4 sizes / 2 weights"
guideline; the deviation is intentional because the paper/ink scale is already validated and shipped on worker surfaces.

| Role | Font | Size | Weight | Line height | Usage |
|------|------|------|--------|-------------|-------|
| Micro-label | JetBrains Mono | 9–10px | 600 | 1.2 | Block-type labels, eyebrows, `.pk-grp`, `kbd`, tags — uppercase, letter-spacing .06–.1em |
| UI / body | JetBrains Mono | 11–12px | 400 / 500 | 1.5 | Rail items, picker rows, tool buttons, measurement/technical values |
| Prose body | Inter (`.prose`) | 13px | 400 | 1.6 | Step descriptions, hazard body, callout body, sign-off text — all long-form block content |
| Section heading | JetBrains Mono | 15px | 600 | 1.3 | `.sec-h h2` section titles (contentEditable) |
| Measurement input | JetBrains Mono | 18px | 500 | 1.2 | `.mbox input` captured value |
| On-ramp display | JetBrains Mono | 26px | 600 | 1.15 | New/Convert on-ramp `h1` only |

**Rule (from design-tokens):** technical content (IDs, numbers, units, timestamps, tool names) = mono by default;
switch to Inter via `.prose` on the content wrapper for human-readable long-form. Every block's editable body text is `.prose`.

**Weights loaded:** JetBrains Mono 300/400/500/600/700; Inter 400/500/600. Primary pair: **400 regular + 600 semibold**; 500 medium for interactive UI affordances.

**Flags (non-blocking, design decisions made in-system):**

Executor MUST NOT introduce a second interactive accent — reuse blue for all edit chrome. Documented so the checker does not flag it as a palette violation.
2. **Purple is not in the 6-semantic set** — it is the AI-origin marker (`--ai`), used for provenance, ghosts, and the deferred agent layer. Reserved strictly for machine-authored/AI signals so workers never confuse it with a safety accent.

## Field-Editor Contract (P14 — the primary deliverable)

D-01 makes P14 **RE-IMPLEMENT all 16 field editors bespoke** (no Puck popover retained). The hard rule
(SPEC acceptance): **no field editable under Puck may become unreachable.** Field shapes are frozen by the
block `*PropsSchema` Zod (`src/lib/validators/blocks.ts` + `puck-config.tsx` `fields`) — reuse that schema as
each panel's validation. The current Puck `fields` map (verified in-repo) is the exact reachability checklist.

Rather than 16 bespoke designs, all fields resolve into **five interaction patterns**:

| Pattern | For field kinds | Where it lives | Visual |
|---------|-----------------|----------------|--------|
| **A — Inline contentEditable** | every Puck `contentEditable:true` text/textarea | on the block card, in place | Click text → blue focus ring (`box-shadow 0 0 0 2px rgba(59,130,246,.22)`), commit on blur. Uncontrolled (Pitfall 4): set defaultValue once, read `textContent` on blur. Never render user text as innerHTML (XSS). |
| **B — Inline enum chip** | single `select` enums | on the block header, in place | Small clickable pill (`.sevpill`/`.toggle`). ≤3 options → click cycles (sketch `cycleSev`). >3 → click opens a tiny anchored menu of the enum values. Colour follows the block's semantic accent. |
| **C — Anchored field panel** | `array` lists + multi-field numeric config | popover anchored to the block's tools row (right/below), ~300px | Card with `.pk`-style chrome. Rows are add/remove list items (drag to reorder via dnd-kit). Opens on a "⚙ edit fields" tool button; Esc/click-away closes; autosaves on change. |
| **D — Inline editable token** | inline numeric/range tokens | on the block body, in place | Dashed-underline editable span (`.tol` orange for tolerance; step number chip). Type-in-place, mono font. |
| **E — Media grid + medium picker** | photo/visual item arrays | on the block card | Thumbnail grid (`.vmedia`) with `＋ add media`; each add opens the medium sub-picker (photo upload / diagram→Konva / video). Per-item: caption inline (A), alt in item popover (C). |

## Visual Block + Konva Annotation Editor (R5 / D-03 — Phase 17 absorbed)

### Visual block on the canvas (Pattern E)
Cyan-framed card (`--accent-mcu`). Media grid `.vmedia`: 3-up thumbnails + `＋ add media`. Each item shows its
medium tag pill (`visual:photo` cyan / `visual:diagram` blue / `visual:video` pink). `＋ add media` opens the
medium sub-picker (the inserter's `pageVisual` — Photo/Diagram/Video). A single block holds mixed media.

### The annotation editor — how it OPENS
- **Full-screen modal overlay** (not a popover), launched from a diagram item's "annotate" action. `dynamic(() => import('.../visual/AnnotationEditor'), { ssr:false })` — **admin-only, never in the worker bundle**.
- Modal chrome: steel-900 header bar (matches top chrome), paper canvas body, 6px max radius. The image renders at its **natural dimensions** in a scroll container (coordinate stability — Konva pitfall #2).

### Toolbar (left or top rail inside the modal)
Primitives, each a mono-labelled icon button (Lucide), one active at a time:

| Tool | Konva primitive | Icon |
|------|-----------------|------|
| Arrow | `Konva.Arrow` (bendable via points + tension) | ArrowUpRight |
| Rectangle | `Konva.Rect` (dashed option) | Square |
| Ellipse | `Konva.Ellipse` | Circle |
| Text | `Konva.Text` (via `<textarea>` overlay for editing) | Type |
| Numbered callout | `Konva.Label` (tag+text) — auto-incrementing number | Hash / MapPin |
| Freehand | `Konva.Line` (tension smoothing) | PenTool |

Annotation stroke colours default to the semantic accents (brand-yellow `#fbbf24` primary, hazard red for warnings)
— NOT arbitrary. Selection/transform via `Konva.Transformer` (resize/rotate handles).

### Editor controls
| Control | Behaviour |
|---------|-----------|
| Undo / redo | Scene-snapshot stack (Undo2 / Redo2). |
| Select / transform | Click a shape → Transformer handles; Delete key removes; drag to move. |
| Stylus "Pen only" toggle | Palm-rejection — filter `pointerType==='pen'` (Konva pitfall #5). Toggle button in the toolbar; on for iPad. |
| Save | Writes `scene` jsonb + `natural_width/height` to `sop_image_annotations` (RLS org-scoped, service-role write self-enforces org — RESEARCH security). Non-destructive: image URL stays OUT of the scene. |
| Close | Returns to the canvas; the diagram thumbnail updates. |

### DiagramHotspotBlock (the only freeform surface)
Numbered callouts placed at **freeform x/y in natural-image space**. This is the single exception to block-reflow —
called out so the checker does not flag free positioning as a layout violation. Folds into the Visual/diagram medium.

### Worker render of a baked diagram
On publish, client `stage.toDataURL()` → baked PNG → `sop-images/baked/{sop}/{image}.v{N}.png` (content-versioned,
beats CDN cache). **Worker read path serves the baked PNG via `<img>` only — never imports Konva** (HARD CONSTRAINT
D-03; bundle gate enforces Konva absent from `/sops/[sopId]`). The worker sees a flat annotated image identical to
what the admin drew.

## Inserter + Ghosts (R3 / R4 — encoded from the sketch, LOCKED)

Encoded verbatim from `sketches/sop-builder-redesign/index.html` (`LANE`/`SMART`/`GROUPS`/`LIB`/`SNIP`, `renderPicker`,
`injectGhosts`/`refreshGhosts`). Contract restated for the checker:

**Paged inserter** (`.picker`, 320px, `1.5px --ink-900`, 10px radius): home page = search + one smart row (purple,
"↵ or Tab") + "Fits here" (LANE by section render-family) + drill rows (More block types / Reuse / Describe with AI).
Keyboard: `↑↓` move (with `.hi` highlight), `↵` insert-or-drill, `esc` close, type-to-filter. Reuse page = dept-scope
segmented toggle (Forming dept / All departments) over `BlockPicker` (reuse existing Phase 13 path — do not rebuild).

**Smart ghosts** (`.ghost`, dashed purple): render after block *i* iff `SMART[type(i)]` exists AND `type(i+1) !==
predictedType` (self-suppress when redundant). Exactly one "live" near viewport-center; others `.dim` (opacity .3);
scrolled-past (`bottom<64px`) → `.gone` permanently. `Tab` accepts the live ghost; typing inside a block `.gone`s all
ghosts except the one immediately after it. rAF-throttled class toggles on refs — NEVER re-render the document on scroll.

## Responsive

Desktop-first admin builder; **must not break ≥768px** (constraint).

| Breakpoint | Behaviour |
|-----------|-----------|
| ≥861px | Full builder: 220px rail + canvas grid; stepper visible. |
| 768–860px | Rail + stepper collapse (`@media(max-width:860px)` hides `.rail`, `.stages`, single-column canvas). Inserter/ghosts still function. Must remain usable (admin edge case, not primary). |
| Mobile-preview toggle | **First-class primitive.** Desktop/Mobile segmented control in top chrome. Mobile = 390px phone frame (`.phone`, steel-900 10px bezel) rendering the SAME blocks one-column — proves the worker view without a device. `body.phoneview` hides the rail, sets `.doc` to full width. |

Phone frame is a **preview of worker render**, not an edit surface — editing happens on the desktop canvas; the frame
validates the mobile result. This is the "edit once, both render the same source" contract.
