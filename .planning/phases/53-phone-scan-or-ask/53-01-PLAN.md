## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → middleware | The requested path becomes `?next=`; attacker-controlled when someone crafts a link |
| browser → `/login` page and `loginWithEmail` action | `next` arrives from the query string and from the client form call |
| QR payload → app (consumed in 53-05) | A scanned string is arbitrary text from a physical sticker |
| npm registry → build | `jsqr` enters the dependency tree |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-03 | Tampering / Spoofing (open redirect) | `?next=` in middleware, login page, `loginWithEmail` | mitigate | `safeNextPath`: leading `/` only, no `//`, no backslash, no control characters, same origin after URL resolution, never `/login*` or `/api/*`, ≤ 512 chars; applied at all three hops so a forged client call is re-checked server-side; unit tests cover each bypass shape |
| T-53-02 | Spoofing | `extractMachineCode` / `isOurPlateUrl` | mitigate | Exact origin equality with a caller-supplied origin (no hardcoded host), exact `/m/<code>` path, Crockford pattern; returns only the normalised code so callers rebuild `/m/${code}` and never navigate to scanned text; look-alike host, scheme, extra-segment and `javascript:` cases unit-tested |
| T-53-SC | Tampering (supply chain) | `npm install jsqr` | mitigate | slopcheck `[OK]` recorded in RESEARCH; executor re-asserts registry metadata (version, Apache-2.0, cozmo/jsQR repo, no install scripts, no dependencies) before installing and stops on any mismatch; `--save-exact`; lockfile committed |
| T-53-01-A | Information Disclosure | eval skeleton | accept | Every test is fixme and the describe self-skips without EVAL env — nothing touches production in this plan |
