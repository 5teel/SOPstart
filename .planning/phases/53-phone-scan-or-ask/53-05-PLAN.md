<objective>
Add the in-app scanner: a Scan a machine plate button on the phone home that opens a full-screen camera sheet, decodes the plate's QR (native `BarcodeDetector`, else `jsqr`), and client-routes to `/m/<code>` — with a typed-code fallback that is always one tap away.

Purpose: PHN-03 and the last piece of PHN-01's phone home. On an iPhone there is no `BarcodeDetector` at all (RESEARCH Pitfall 4), so the `jsqr` path is the main path for a large share of NZ workers, not an edge case; and a gloved worker on a dusty machine may never get a clean read, so typing the code printed on the plate must always work.

Output: `ScanSheet.tsx` · the Scan button + lazy sheet in `PhoneHome` · a `scan sheet (53 D-09)` forbidden-marker group on both gated routes · the phone flow on `/pathways` · a clean build with the jsqr chunk size recorded.

`router.push` is deliberate here (D-07): one navigation after a successful scan, not a hot click path — the CLAUDE.md 2026-05-13 learning is about repeated search-param pushes and does not apply.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| camera → decoder | Any QR in front of the lens is attacker-controllable text |
| typed code → navigation | Free text from the worker |
| device camera stream | A live sensor the sheet must release |
| `/sops` base bundle → scan chunk → jsqr chunk | The decoder must stay lazy |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-02 | Spoofing / open redirect | scanned QR → navigation | mitigate | `extractMachineCode(text, window.location.origin)` (exact origin, exact `/m/<code>` path, Crockford pattern — unit-tested in 53-01); the single `router.push` is built as `/m/${code}` from the validated code, never from scanned text; foreign plates show a message and do nothing; spec pins the single push and its argument |
| T-53-04 | Information Disclosure / privacy | camera stream | mitigate | Video only (`audio: false`); `stopCamera` stops every track on close, type-instead, successful scan and unmount (sheet is mounted only while open, so leaving the page unmounts it); decoding is local (`BarcodeDetector` or in-page jsqr on a canvas); the file contains no `fetch`, `toDataURL`, `toBlob` or upload — asserted by spec |
| T-53-04-B | Tampering | typed code | mitigate | `normaliseMachineCode` (trim, upper-case, Crockford pattern) before navigation; invalid input shows an error and never navigates |
| T-53-16 | Denial of Service (battery/CPU) | decode loop | mitigate | 200 ms `setTimeout` throttle, jsqr frames downscaled to ≤ 640 px wide, loop cancelled and timer cleared on unmount |
| T-53-17 | Elevation of Privilege (bundle) | `/sops`, `/sops/[sopId]` | mitigate | ScanSheet only via `next/dynamic` inside PhoneHome (itself lazy); jsqr only via `import('jsqr')` inside ScanSheet, and only without `BarcodeDetector`; `scan sheet (53 D-09)` marker group on both gated routes; ±2 KB gate against the untouched baseline |
</threat_model>
