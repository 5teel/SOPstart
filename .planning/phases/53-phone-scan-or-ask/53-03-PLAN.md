<objective>
Give every machine an address and a printable label: the `/m/<code>` page that lists that machine's procedures for the signed-in worker, and the A6 plate an admin prints from the site editor.

Purpose: PHN-02. A plate on the machine is only useful if the URL it carries opens the right list for whoever scans it, never leaks another organisation's machine, and shows the same badges the worker sees everywhere else. Scanning works from the phone's own camera app as soon as this plan ships (the QR holds an absolute https URL); the in-app scanner arrives in 53-05.

Output: `MachinePanel` inline variant · `MachineView.tsx` · `/m/[code]/page.tsx` · a live cross-org probe · the plate page + `PrintButton` · "Print plate" in `SiteWorkspace` · `journeys.ts` routes · capability matrix rows.

Decisions taken here (Claude's discretion, recorded):
- `/m` reuses `MachinePanel` through a new `inline` prop instead of a second row renderer — one panel, two placements (RESEARCH Pitfall 2).
- QR is server-rendered SVG with the already-installed `qrcode` (the `/admin/sops/[sopId]/qr` precedent); no QR encoder ever reaches a client bundle. The `color` option is omitted (library default is black on white) so the page carries no hex literal and needs no design-token allowlist entry.
- Origin: CONTEXT D-05 names `NEXT_PUBLIC_APP_URL`, which does not exist in this codebase; the existing variable is `NEXT_PUBLIC_SITE_URL` (used by the SOP QR page, invite links and the Shotstack callback). Use it, falling back to the request origin from `headers()` — never a hardcoded host.
</objective>
