<objective>
Lift the worker's per-SOP derivation out of `SopsSection` (in `src/app/(protected)/sops/page.tsx`) into one hook, `useWorkerSops`, without changing a single rendered row — so Phase 53's `/m/<code>` page (53-03) can show the same badges the `/sops` list and plant show.

Purpose: CONTEXT D-04 requires `/m/<code>`'s badges to come from `plantRelState` "fed by `useAssignedSops`". `plantRelState` consumes a `WorkerSop`, and today the only code that builds a `WorkerSop` (assignment lookup, library rows, lineage-rooted last completion, refresher window, newer-version check) lives inline in `SopsSection`, ~180 lines across four queries. Copying it into `/m` would be the exact two-classifiers drift CLAUDE.md 2026-09-27 records; lifting it is the only way `/m` and `/sops` stay in agreement.

Output: `src/hooks/useWorkerSops.ts`; `SopsSection` calling it; the page-reading guards repointed in the same change; a clean build.

Why a separate plan (deviation from the orchestrator's 5-plan outline, recorded): this refactor touches `sops/page.tsx`, which 53-04 (the phone seam) must also edit, and `/m` (53-03) depends on the hook. Putting it in its own Wave-1 plan lets 53-03 and 53-04 run in parallel in Wave 2 with disjoint files; folding it into 53-01 would push that plan past the context budget (4 tasks). It runs in parallel with 53-01 (no shared files) and uses only already-registered test projects.
</objective>
