## Deviations from Plan

**1. [Rule 1 - Bug] addBlockToSection uses `sopSectionId` not `sectionId`**
- **Found during:** Task 2 TypeScript compilation
- **Issue:** TypeScript error `Object literal may only specify known properties, but 'sectionId' does not exist in type` — the correct field name is `sopSectionId` per the action's type definition.
- **Fix:** Changed `sectionId: activeSection.id` to `sopSectionId: activeSection.id` in `handleLibraryAdd`.
- **Files modified:** src/app/(protected)/admin/sops/builder/[sopId]/BuilderClient.tsx
- **Commit:** 493c206 (corrected before commit)

**2. [Rule 1 - Bug] componentIdToType map needed for block-type detection in onItemSelected**
- **Found during:** Post-Task-2 code review
- **Issue:** Initial implementation used `props['__componentType']` to detect block type inside `onItemSelected`, but Puck does not store a `__componentType` key in layout_data props. The block type lives at `item.type` in the layout_data content array, not inside `item.props`.
- **Fix:** Extended the `componentIdToProps` useMemo to also return a `componentIdToType` map (both derived in a single layout_data parse pass). `onItemSelected` now uses `componentIdToType.get(componentId)` for structured-block detection.
- **Files modified:** src/app/(protected)/admin/sops/builder/[sopId]/BuilderClient.tsx
- **Commit:** 933ec3e

**3. [Rule 2 - Type cast] `activeSection` cast as `any` for BuilderTreeRail prop**
- **Found during:** Task 2 TypeScript compilation
- **Issue:** `SopSection.layout_data` is typed as `unknown` while `BuilderTreeRail` expects `SectionWithContent` with `layout_data?: { content?: unknown[] } | null`. The cast is safe — `BuilderTreeRail` defensively checks `layout_data?.content` at runtime.
- **Fix:** `(activeSection ?? null) as any` cast at the BuilderTreeRail mount site.
- **Files modified:** src/app/(protected)/admin/sops/builder/[sopId]/BuilderClient.tsx
- **Commit:** 493c206
