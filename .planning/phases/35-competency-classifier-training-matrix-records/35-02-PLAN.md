<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → server action | Filter inputs (deptId, workerId, sopId, date range) arrive from the admin UI — untrusted, validated by Zod, never used to widen org scope. |
| server action → admin client | createAdminClient() bypasses RLS (service role) — the ACTION must self-enforce organisation_id on every query and role-gate before any org-wide read. |
| worker → getMyCompetencyStates | A worker session reads its own competency — must be strictly self-scoped to auth.uid(), never reachable to peers' rows. |

| T-35-02-02 | Elevation of Privilege | role-check-missing on an org-wide read (the 00054 class, recurred 4×) | mitigate | RECORDER_ROLES.includes(role) gate BEFORE any org-wide read in matrix/record/CSV; source-contract test asserts the gate exists on all three; runtime probe denies a worker session. |
| T-35-02-03 | Information Disclosure | getMyCompetencyStates over-share (worker sees peers) | mitigate | Self-scoped: session client filtered by userId only, no admin client, no role gate; source-contract asserts absence of createAdminClient/RECORDER_ROLES; runtime probe asserts own-rows-only. |
| T-35-02-04 | Spoofing / Information Disclosure | CSV export as an under-authenticated route | mitigate | exportTrainingCsv stays a role-gated 'use server' action (getSessionContext) returning a string — NO cookie-less/bearer/cron /api route (RESEARCH Security threat 3); source-contract asserts no api/competency route added. |
