<objective>
Wire the Wave-1 primitives into the live voice loop: replace the stubbed mic in `WalkthroughVoiceModal` with the real Deepgram stream, classify final transcripts with `classifyIntent`, route navigation commands through `MobileWalkthrough.handleMarkComplete` (the D-02 safety-gated path), and read answers + step text aloud with `useTtsPlayback`. This closes VDW-VOICE-01/02/03 and the voice half of VDW-LIT-03.

Purpose: This is the integration plan — it touches the three coupled components (modal + MobileWalkthrough + WalkthroughSwitcher) that together form the voice→state→audio loop. It is sequenced into Wave 2 (after the Plan 02 infra ships) because it consumes `startVoiceStream(keyterms)`, `classifyIntent`, `extractKeyterms`, and `useTtsPlayback`, and because the modal is the shared concern no other plan may touch. It also `depends_on` Plan 04 (the always-on visual layer) so the Wave-2 human UAT (Task 3) can validate the visual layer (VDW-LIT-01/02) in the same authenticated run — that UAT step has nothing to verify until 04 is merged.

The central wiring challenge (confirmed by source audit): `WalkthroughSwitcher` currently renders `MobileWalkthrough` and `WalkthroughVoiceModal` as SIBLINGS, so the modal has no access to `handleMarkComplete`/`handleStepChange`/`currentStep`. This plan adds a `useImperativeHandle` on `MobileWalkthrough` and a `ref` in `WalkthroughSwitcher` to bridge them — the RESEARCH-preferred additive option (no broader state hoist).

The reactivity trap (the second integration hazard, CLAUDE.md 2026-06-08): `mwRef.current.currentStepText` is a REF read — React does not re-render when the underlying step advances, so a `currentStepText` prop wired straight from `mwRef.current?.currentStepText` in JSX would feed the modal a STALE string and the TTS read-aloud `useEffect(..., [currentStepText])` would fire on the OLD step (or never re-fire). The switcher MUST mirror `currentStepText` into a `useState`, set via `setCurrentStepText(mwRef.current?.currentStepText ?? '')` AFTER each ref advance call (and on modal-open), so the fresh value flows through props and re-triggers the modal effect.

Output: A working push-to-talk voice walkthrough on the mobile immersive surface, with a hard human-verify checkpoint (a real authenticated browser run is mandatory — source-contract specs cannot prove the mic→TTS→advance loop, per CLAUDE.md 2026-06-05 / 2026-06-08).
</objective>
