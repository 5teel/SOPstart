## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/voice/tts | Untrusted worker input (text) crosses into a paid OpenAI call — the abuse / cost surface |
| browser → Deepgram WebSocket | Mic audio + keyterms leave the device; ephemeral token (minted by existing /api/voice/token) is the only credential on the wire |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-02-01 | Denial of Service | /api/voice/tts (50 workers × 500-char loops) | mitigate | zod `max(500)` input cap + per-user in-flight Set (429 on second concurrent call), identical to /api/voice/query; `maxDuration = 30` caps runaway calls |
| T-22-02-02 | Elevation of Privilege | /api/voice/tts as a free OpenAI proxy | mitigate | `supabase.auth.getUser()` required (401 without session); regular RLS client, NOT service-role; text length bounded so it cannot be used for arbitrary long generations |
| T-22-02-03 | Tampering | TTS prompt injection via `text` | accept | TTS input is read-aloud text only; OpenAI TTS does not interpret HTML/markup; `instructions` param is a static server constant — no worker input reaches a system prompt. Low risk, no PII in step text |
| T-22-02-04 | Information Disclosure | error logs leaking request body | mitigate | catch logs only `error.message`, never the body (mirrors T-15-03-05) |
| T-22-02-05 | Tampering | hardcoded TTS model id rotting silently (200 + 0-byte audio) | mitigate | `TTS_MODEL` shared constant with `process.env.TTS_MODEL` override (2026-06-02); SUMMARY notes monitoring `content-length` for the 0-byte rot signature |
| T-22-02-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages (RESEARCH § Package Legitimacy Audit: not applicable — all deps already installed) |
</threat_model>
