<objective>
Close verification gap **WR-02 (Warning)**: `materializeSopAccessForOrg` (`src/actions/grants.ts:511-517`) is a one-way visibility ratchet. When a SOP gains its first SOP-target grant it force-writes `sops.all_departments = false` (correct — closes the 00035 bypass), but when the LAST SOP-target grant is revoked there is no restore branch. For a pre-Phase-32 org-wide SOP (`all_departments = true`, in a collection that carries no grants — the default state for any org that never opened the Access map), one override→revoke round trip leaves `all_departments = false` AND an empty replace-written `sop_departments`/`sop_access_people`. The SOP becomes silently invisible to every worker, breaking the AccessAnswerPanel's own promise: "Remove all named people and this SOP follows its collection again."

Fix (per 33-REVIEW.md WR-02, first-listed direction): snapshot the pre-override `all_departments` value on first override and restore it on re-follow. A snapshot column is the only approach that distinguishes a legacy org-wide SOP (was `true`) from a collection-following SOP (was `false`) — both hit the re-follow-resolves-to-empty path, but only the org-wide one should regain org-wide visibility. This is what makes the required test's "confirm visibility restored" assertion correct for the org-wide case while keeping the collection-following case at `all_departments = false`.

Purpose: Honor SC-4 ("no stale visibility after revoke/override") for the one precondition the shipped live tests never exercised. Worker visibility to safety SOPs is a trust boundary — under-exposure (invisible) is an operational failure.
Output: migration 00051 (nullable snapshot column), snapshot/restore logic in `materializeSopAccessForOrg`, and a new live-runtime test proving restore.
</objective>
