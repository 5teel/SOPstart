# Phase 21.5 Plan 04: Review Station Summary

3-zone Review Station with step navigator, inline per-step AI safety check, and source document pane — one step at a time, all zones synced on selection.

## What Was Built

### Task 1: NavRow.tsx (navigator row component)

Presentational single-row component for Zone 1 (step navigator). Renders per UI-SPEC § "Zone 1":

- **Check dot** (16×16px, border-radius 50%): empty = `--ink-300` border; verified = filled `--accent-ok` with white `✓`
- **Kind pill** (74px fixed, 10px/600/uppercase): label from `humanizeBlockType(block.type)`, color from `BLOCK_TYPE_LABELS.pillVariant` → `getPillStyle()` inline styles
- **Label** (flex-1 truncated): `block.preview` with full text in `title` attr
- **Flag badge** (16px circle, `--accent-hazard`): only when `flags_count > 0 && !verified`
- Row states: default transparent border → active `--accent-step` border + `#eff4ff` bg → verified muted text
- `data-testid="nav-row"`, `data-block-id`, `data-active`, `data-verified` attributes on root
- No raw `block.type` rendered anywhere; always `humanizeBlockType(block.type)`

### Task 2: ReviewStation.tsx (3-zone grid)

Full Review Station component with three synchronized zones:

**Zone 1 — Step Navigator (left)**
- Zone header: "Steps in this SOP" / "Click any step to review it"
- Maps all `checklist.blocks` to `<NavRow>` with `onSelect` calling both `setActiveIdx(idx)` and `setActiveProvenance(block.provenance, block.id)`
- Empty state: "Nothing to verify yet" / "Add content in the Build stage..."
- Loading state: "Loading checklist…"
- Auto-scrolls active row into view on `activeIdx` change

**Zone 2 — Step in App (centre)**
- Zone header: "The step, in the app" / "This is what the worker will see on their phone"
- Renders ONE step card keyed on `activeBlock.id` (1.5px `--accent-step` border, white bg)
- Card anatomy: orientation strip (type pill + step counter), h2 title, body prose
- Inline AI Safety Check panel immediately below card:
  - Status dot (`--accent-ok` clean / `--accent-measure` with flags)
  - Label: "AI safety check · N thing(s) to look at" or "AI safety check — all clear"
  - `<RerunReviewerButton>` restyled via className
  - `<ReviewerFlagsPanel>` renders null when no flags → no AI chrome for clean steps
- NO standalone global reviewer flags panel

**Zone 3 — Original Document (right)**
- Zone header: "Original document" / "Auto-scrolled to the part this step came from"
- `<SourceViewerPane sopId sourceType transcriptSegments />` rendered as-is
- Subscribes to selection-sync via its own `useSelectionSync` consumer

**Action Bar (spans zones 2+3 desktop / full width tablet)**
- "◀ Previous step" ghost button → `Math.max(0, activeIdx-1)`
- "✓ Looks right — verify step" primary button (`--accent-ok`) → `approve(activeBlock.id)` + advance to next unverified
- "✎ Send back to edit" button (`--accent-measure` text/border) → `decline(activeBlock.id)`
- Keyboard hint: `or press A verify · D edit · J/K next/prev` with `<kbd>` elements

**Responsive layout (CSS only, no JS breakpoints)**
- ≥1024px: `grid-template-columns: 280px 1fr 1fr`; action bar `grid-column: 2/4`
- 768–1023px: `grid-template-columns: 240px 1fr`; Zone 3 hidden; "Show source" drawer toggle in Zone 2 header (`aria-label="Show original document"`); action bar spans full width

**Data layer reused unchanged:**
- `useVerifyChecklist(sopId)` — blocks/activeIdx/setActiveIdx/approve/decline
- `useReviewerFlags(sopId)` — byBlockId for flag count header
- `useChecklistKeybinds(...)` — j/k/a/d/Enter bindings, exactly as VerifyChecklistGate
- `useSelectionSync().setActiveProvenance` — syncs source pane on row select
- No new fetch/mutations, no `verifyBlock`/`unverifyBlock` direct calls

**block-type-labels.ts in worktree:** This Wave-2 worktree is based on commit `2f18028` (pre-Wave-1 merge). Wave 1 was merged to master at `d18a002` but this worktree's base was not updated. The orchestrator's merge will deduplicate naturally (same content, same path).
