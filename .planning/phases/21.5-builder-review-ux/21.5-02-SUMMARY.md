# Phase 21.5 Plan 02: BuilderStageStepper + OrientationStrip Summary

**One-liner:** Controlled stepper chip row (adaptive 2/3-stage with inline publish reason) + Review-stage orientation strip with exact copywriting prose and progress bar, both fully presentational.

## What Was Built

### Task 1: BuilderStageStepper

`src/app/(protected)/admin/sops/builder/[sopId]/BuilderStageStepper.tsx`

A fully controlled presentational component that renders the Build → Review → Publish chip row inside the dark top bar. Key characteristics:

- **Adaptive mode:** 3 chips (Build → Review & verify → Publish) when `hasSourceDoc=true`; 2 chips (Build → Publish) when `hasSourceDoc=false`
- **Chip states:** done (green filled dot + ✓ tick, `--accent-ok` text), active (white bg, `--ink-900` text, blue filled dot with number), todo (transparent, `--ink-500` grey text, empty dot border)
- **Interactivity:** clickable chips navigate via `onStageSelect`; Publish chip gets `disabled`+`aria-disabled` when `!isReady`; Review chip disabled when `!hasSourceDoc`; Build always clickable
- **Inline publish-gate reason:** `data-testid="stepper-publish-reason"` span rendered BELOW chip row when `!isReady` showing `🔒 N of M steps left to verify` (JetBrains Mono 10px `#a1a1aa`); absent from DOM when `isReady`
- **Responsive:** CSS media query hides `.stepper-chip-label` text at 768–1023px (number circles only with `title` tooltip); full labels at ≥1024px
- **Test hooks:** `data-testid="builder-stage-stepper"` + `data-active-stage={activeStage}` on root

### Task 2: OrientationStrip

`src/app/(protected)/admin/sops/builder/[sopId]/OrientationStrip.tsx`

A fully controlled presentational component for the Review-stage orientation strip below the top bar:

- **Layout:** flex row, align-items center, gap 8px, padding 8px 16px, white background, 1px `--ink-300` border-bottom
- **Stage badge (left):** blue filled badge (`--accent-step` bg, white text, 10px/weight 600/radius 2px) showing `stageBadge` prop
- **Review prose (centre):** exact verbatim text from Copywriting Contract: "Check each step against the original document, then mark it verified. The AI safety check flags anything that looks off." (Inter 12px `--ink-700`)
- **Progress (right):** JetBrains Mono `{verifiedCount} / {totalCount} verified` counter + 120×4px horizontal progress bar (`--ink-200` bg, `--accent-step` fill, border-radius 3px)
- **Accessibility:** progress bar has `role=progressbar` with `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, `aria-label`
- **Test hook:** `data-testid="orientation-strip"` on root

## Deviations from Plan

None — plan executed exactly as written.

**Design token approach:** The UI-SPEC references CSS variable names (`--accent-step`, `--accent-ok`, `--ink-200`, `--ink-700`) that either aren't defined in `:root` or have different values in `blueprint-theme.css` (which defines `--ink-700: #27272a` rather than the UI-SPEC value `#3f3f46`). Hardcoded hex values from the UI-SPEC Color section are used directly in inline styles. This ensures the components render correctly regardless of which CSS file is loaded.
